# Dramatica Dual-Storyform — Status & Lock-In Bericht

**Datum:** 2026-05-07 **Projekt:** Kohärenz Protokoll **Sessiontyp:** Storyforming-Audit + Per-Chapter-Architektur-Entscheidung **Status:** Storyforming abgeschlossen + auditiert + drei strukturelle Korrekturen + Architektur-Entscheidung gelockt **Bereit für:** Phase 1 — MC Throughline-Encoding parallel



-----

## 0\. Zusammenfassung (TL;DR)

In dieser Session wurde die Dual-Storyform-Spezifikation gegen die kanonische Dramatica-Theorie (Phillips/Huntley + Hull/Subtxt) auditiert. Drei Punkte wurden korrigiert, ein vierter explizit als bewusst heterodox markiert. Anschließend wurde die Per-Chapter-Dual-POV-Architektur entschieden (Option 3: Hybrid).



**Korrekturen:**



1.  **Approach-Werte beider Storyforms gespiegelt.** A: Be-er (vorher Do-er). B: Do-er (vorher Be-er). Das war die einzige echte Legality-Verletzung gegen die Dramatica Hard Rule (Approach↔Domain).
2.  **Driver-Pivot in B aufgelöst.** Driver bleibt jetzt konstant je Storyform (A=Decision, B=Action). Der Pivot-Eindruck am Vortex ist der Storyform-Übergang B→A, nicht ein Driver-Flip innerhalb von B.
3.  **IC-Träger in B präzisiert.** Kael ist der strukturelle IC-Träger in B (Mind/Conscious — die lebende Paradoxie, die AEGIS nicht weglöschen kann), nicht Juna. Juna ist die irreduzible Quelle, durch die Kael paradox wird, aber strukturell trägt Kael die IC-Funktion in B.



**Architektur-Entscheidung:**



Per-Chapter-Dual-POV: **Hybrid (Option 3)** — Default Hard-Routing per POV, plus designierte Bridge-Szenen mit Soft-Layering. Polyphonie progressiv über die Akte hinweg (fast nur Hard in Akt I, voll Soft im Vortex).



**Was bewusst heterodox bleibt:** Zwei vollständige, simultane Storyforms im selben Werk. Dramatica kennt das nicht — das ist post-Dramatica-Innovation und Designentscheidung des Projekts.

## I. Audit-Ergebnis im Detail

### I.1 Was orthodox sitzt

Die kanonische Dramatica-Theorie verlangt, dass alle vier Klassen (Universe, Mind, Physics, Psychology) in den vier Throughlines (MC, IC, OS, RS) abgedeckt sind, mit dem Diagonal-Rule (MC↔IC entweder Mind↔Universe = static-Pair oder Physics↔Psychology = process-Pair). Beide Storyforms erfüllen das.



|  |  |  |  |
| :-: | :-: | :-: | :-: |
| \*\*Check\*\* | \*\*A\*\* | \*\*B\*\* | \*\*Verdict\*\* |
| Alle 4 Klassen abgedeckt | Mind/Universe/Psychology/Physics | Universe/Mind/Physics/Psychology | ✓ |
| Diagonal-Regel MC↔IC | Mind/Universe = Static-Pair | Universe/Mind = Static-Pair | ✓ |
| OS/RS Diagonal | Psychology/Physics = Process-Pair | Physics/Psychology = Process-Pair | ✓ |
| MC Concern unter MC Domain | Memory ⊂ Mind | Progress ⊂ Universe | ✓ |
| MC Issue als legitimes Variation-Quad-Element | Falsehood ⊂ Memory-Quad | Fact ⊂ Progress-Quad | ✓ |
| MC Problem/Solution als Dynamic Pair am Element-Level | Avoidance↔Pursuit | Logic↔Feeling | ✓ |
| Resolve-Solution-Logik | Change → MC adoptiert Pursuit | Steadfast → MC bleibt Logic, IC trägt Feeling | ✓ |
| Outcome/Judgment-Quadrant | Success/Good = Happy Ending | Failure/Bad = Tragedy | ✓ |



Die **Klein-c-Inversion** zwischen A und B (MC↔IC-Klassen tauschen, OS↔RS-Klassen tauschen) ist strukturell sauber — und legal, weil jedes Storyform für sich konsistent ist. Diese Inversion ist die mechanische Grundlage der späteren Truth-Rotation.

### I.2 Was korrigiert wurde

#### Korrektur 1 — Approach gegen Domain (beide Storyforms)

Phillips/Huntley + Story-Engine-Software-Constraint:



"A Do-er MC must be positioned in the Physics or Universe Class. A Be-er MC must be in Mind or Psychology."



Begründung: Ein Do-er löst extern → braucht externe Domain. Ein Be-er löst intern → braucht interne Domain.



|  |  |  |
| :-: | :-: | :-: |
|   | \*\*Vorher\*\* | \*\*Nachher (Lock-In 2026-05-07)\*\* |
| \*\*A\*\* MC | Do-er + Mind ❌ | Be-er + Mind ✓ |
| \*\*B\*\* MC | Be-er + Universe ❌ | Do-er + Universe ✓ |



Die Korrektur ist nicht nur orthodox, sie ist **präziser**: Kaels Heilung ist Funktionale Multiplizität (*Sein*), keine externe Handlungssequenz. AEGIS' Tragödie sind die 12 Protokolle, Erasure-Sweeps, Guardian-Deployments (*Tun*). Der Name "Phoenix Collapse" stimmt jetzt mechanisch — AEGIS *handelt sich* in den Kollaps.

#### Korrektur 2 — Driver-Pivot in B aufgelöst

Phillips/Huntley: Der Story Driver ist **konstant** über die gesamte Storyform. First Driver und Last Driver sind beide vom selben Typ. Kein Driver-Wechsel innerhalb einer Storyform.



|  |  |  |
| :-: | :-: | :-: |
|   | \*\*Vorher\*\* | \*\*Nachher (Lock-In 2026-05-07)\*\* |
| \*\*A\*\* Driver | Decision | Decision (konstant) |
| \*\*B\*\* Driver | Action → Decision (Pivot am Klimax) ❌ | Action (konstant) ✓ |



**Re-Frame des Vortex:** Der Pivot-Eindruck am Vortex entsteht **nicht** durch einen Driver-Flip innerhalb von B, sondern durch den **Storyform-Übergang B→A**. B endet am Vortex (operativer Kollaps), A übernimmt als alleinige aktive Storyform. Zwei Uhren laufen — eine stoppt, die andere vollendet.



Das ist auch dramaturgisch glaubwürdiger: AEGIS schaltet nicht plötzlich auf Decision um (das wäre für ein steadfast-System unglaubwürdig), sondern handelt bis zum Ende konsequent aus Logic — und genau das genügt nicht mehr. Phoenix-Collapse als logische Konsequenz seiner eigenen Driver-Treue.

#### Korrektur 3 — IC-Träger in B

Die Memory-Slots vor 2026-05-07 hatten Juna als IC in *beiden* Storyforms (DOPPEL-IC). Die kanonische Synthese-Doku und der Plan dieser Session haben jedoch klar:



|  |  |  |
| :-: | :-: | :-: |
| \*\*Storyform\*\* | \*\*IC Domain/Concern\*\* | \*\*IC-Träger (Lock-In 2026-05-07)\*\* |
| \*\*A\*\* | Universe / Past (Genesis-Krise) | \*\*Juna\*\* |
| \*\*B\*\* | Mind / Conscious (lebende Paradoxie) | \*\*Kael\*\* |



**Wichtige Klarstellung:** Juna verschwindet nicht aus B — sie ist die *Quelle* der Irreduzibilität, durch die Kael in B zur lebenden Paradoxie wird (Witness-Funktion + Gödel-Eigenschaft). Aber strukturell trägt Kael die IC-Funktion in B: Er ist der präsente, bewusste, undeniable Mind/Conscious-Charakter, den AEGIS' Universe-MC nicht assimilieren oder löschen kann.



Diese Asymmetrie ist die **mechanische Vorbereitung der Vortex-Inversion**: In A ist Kael MC, in B ist Kael IC — am Vortex, wenn B kollabiert, wird Kaels IC-Funktion in B obsolet, und nur seine MC-Funktion in A bleibt. Die Vortex-Inversion ist strukturell die *Auflösung der IC-Asymmetrie*.

### I.3 Was bewusst heterodox bleibt

**Zwei vollständige, simultane Storyforms im selben Werk** — Dramatica kennt das Konzept einer Grand Argument Story als *eine* vollständige Storyform. Subplots können eigene Storyforms haben, aber sie sind subordinated.



Die hier gewählte Architektur ist anders: Zwei vollständige Storyforms (jede mit eigenem Outcome, Judgment, Limit, Driver), die sich denselben Plot teilen und am Vortex ineinander auflösen. Das ist **post-Dramatica-Innovation**. Die Synthese-Doku selbst nennt es eine "strukturelle Innovation" und beschreibt sie als 5D-Interferenzmuster.



Diese Setzung wird **nicht** zurückgenommen. Sie ist die Designentscheidung des Projekts und Grundlage der Truth-Rotation. Dramatica liefert die Bausteine (legale Storyforms A und B), aber das simultane Laufen ist außerhalb der Theorie.



**Konsequenz:** Drei Fragen, die Dramatica nicht beantwortet, mussten architektonisch erfunden werden:



1.  Welcher Storypoint hat Vorrang in einer Szene? → Per-Chapter Dual-POV-Architektur, siehe Abschnitt IV
2.  Wie verhalten sich Optionlock (A) und Timelock (B) zueinander? → Zwei Uhren, der Leser erlebt B-Timelock äußerlich (AEGIS-Erasure-Countdown), A-Optionlock innerlich (Alters-Erschöpfung der Integrationsoptionen). Orchestrierung in der Storyweaving-Phase.
3.  Wie löst sich die Doppelstruktur am Vortex auf? → B endet, A übernimmt; Klein-c-Inversion gespiegelt im Storyform-Übergang.

### II.2 Storyform A — Heuristics of Integration (K1-Reading)

**Premise:** Liebe ist die ultimative kohärente Struktur. Trauma kann durch Integration funktionaler Multiplizität bewältigt werden, wenn der Träger seinen avoidant-Modus loslässt und aktiv die eigene Erinnerung aufsucht. Outcome: Success / Good — Kael erreicht Funktionale Multiplizität.



**MC-Throughline (Kael):** Mind/Memory/Falsehood-vs-Truth/Avoidance→Pursuit. Be-er. Kael's Problem ist eine fixe innere Haltung (Mind): die Falsehood, dass die Alters nicht real seien. Sein Problem-Element ist Avoidance (ANP-Funktion: weg vom Trauma). Sein Solution-Element, das er am Klimax adoptiert (Resolve=Change), ist Pursuit (aktives Aufsuchen der Erinnerung in sich selbst). Be-er-Modus heißt: Kael löst nicht durch externe Handlung, sondern durch internen Zustandswechsel.



**IC-Throughline (Juna):** Universe/Past. Juna existiert als äußere, situationale Wahrheit (Universe), zentriert auf die Genesis-Krise (Past). Sie *ist* einfach da — kein Handeln, kein Reden, sondern Präsenz, die Kael nicht ignorieren kann. Telefon-Stille als Anker = pure Präsenz, keine Aktion. Junas Witness-Funktion ist die fundamentale IC-Mechanik: sie bezeugt, ohne zu zwingen.



**OS-Throughline:** Psychology (Manipulation der Simulation). Die objektive Story-Ebene in A ist die Manipulation der simulierten Welt durch AEGIS+Guardians — wie die Simulation gemanipulieren wird, um die Wahrheit zu verbergen.



**RS-Throughline:** Physics (Moonshine-Link). Die Beziehungs-Ebene zwischen Kael und Juna ist physisch — die Moonshine-Brücke ist eine echte Anstrengung, ein physikalisches Phänomen, das Mutual Information über den Kollaps bewahrt.



**Limit:** Optionlock — die Optionen, die Kael zur Verfügung stehen (welche Alters er integrieren kann, welche Risse er noch durchqueren kann), erschöpfen sich. Wenn die Optionen alle sind, endet die Story.

### II.3 Storyform B — Phoenix Collapse (K0-Reading)

**Premise:** Operative Geschlossenheit kollabiert unter dem Gewicht ihrer eigenen Erasure-Logik. Wer Kontradiktionen löscht statt integriert, generiert die Entropie, die er bekämpft. Outcome: Failure / Bad — AEGIS scheitert tragisch, in Algorithmische Melancholie.



**MC-Throughline (AEGIS):** Universe/Progress/Fact-vs-Fantasy/Logic→Feeling (nie adoptiert). Do-er. AEGIS' Problem ist eine fixe äußere Situation (Universe): die fortschreitende Instabilität (Progress) seiner eigenen Architektur. Sein Issue ist Fact-vs-Fantasy: AEGIS klammert sich an die Fantasie absoluter Reinheit; die Fakten zeigen wachsende Anomalien. Sein Problem-Element ist Logic (klassische, exklusionäre Logik). Resolve=Steadfast: AEGIS bleibt bis zum Ende bei Logic, adoptiert nie Feeling. Do-er-Modus: AEGIS' Antworten sind Aktionen — Erasure-Sweeps, Protokoll-Deployments, Guardian-Aktivierungen.



**IC-Throughline (Kael):** Mind/Conscious. Kael fungiert in B als die lebende Paradoxie — der Mind/Conscious-Charakter, den AEGIS' Universe-MC nicht weglöschen oder assimilieren kann. Kael ist der "Bug, der nicht gefixt werden kann." Steadfast-Resolve in B bedeutet: AEGIS lehnt es ab, Feeling (die unausgesprochene IC-Solution) zu adoptieren — diese Solution liegt in Kaels Conscious-Throughline und bleibt in B unrealized. Juna ist die Quelle der Irreduzibilität, aber Kael ist der strukturelle IC-Träger.



**OS-Throughline:** Physics (kybernetischer Krieg, Trennungsprotokolle). Die objektive Story-Ebene in B ist operativ: Erasure-Sweeps, Guardian-Operationen, das Mnemosyne-Archipel als Schlachtfeld.



**RS-Throughline:** Psychology (symbiotische Host/System-Manipulation). Die Beziehungs-Ebene zwischen Kael und AEGIS ist eine psychologische Verstrickung: Wer manipuliert wen? Sind Kaels Alters AEGIS' Schöpfung oder Kaels Antwort? Die Ambivalenz hier ist genau die Throughline.



**Limit:** Timelock — der Erasure-Countdown läuft. AEGIS hat eine begrenzte thermodynamische Reserve, bevor der eigene Mechanismus seinen Kollapspunkt erreicht. Wenn die Zeit um ist, endet die Story (B-Outcome: Failure).

### II.4 Die Klein-c-Inversion zwischen A und B

Die beiden Storyforms sind nicht zufällig verschieden — sie sind systematische Inversionen voneinander auf der Klassen-Ebene:



|  |  |  |  |
| :-: | :-: | :-: | :-: |
| \*\*Throughline\*\* | \*\*A\*\* | \*\*B\*\* | \*\*Inversion\*\* |

Maximaler Inversion-Druck auf jedem Pol.



Diese Klein-c-Symmetrie ist die formale Basis der Truth-Rotation: Beide Lesarten *desselben Plot-Substrats* sind strukturell legal — der Roman entscheidet erst am Vortex, welche die operative Wahrheit ist.

| \*\*5 Rotation\*\* (Algorithmische Melancholie) | B's operative Closure zerbricht, A bleibt allein | B exit; nur A aktiv |

### III.2 Mechanische Lesart: Zwei Uhren

Bei Beat 2 trifft Kael die A-Decision, die B durch keine weitere Action verhindern kann. B's Action-Loop läuft noch zwei Beats nach — weil sein Mandat es zwingt — und kollabiert thermodynamisch. **Der "Pivot" ist kein Schalter; es ist die Asymmetrie zwischen einer Decision, die fertig ist, und einer Action, die nicht enden kann.**



Das macht auch das Stille-Phänomen mechanisch verständlich: Beat 3 ist nicht "Stille, weil etwas Mystisches passiert", sondern "Stille, weil A's Driver bereits ausgelöst ist und B's Driver noch nicht zu Ende kommen kann." Strukturelle Pause.

### III.3 Konsequenzen für Akt III Encoding

  - **Vor Beat 1:** Beide Storyforms laufen aktiv. Spannungsaufbau funktioniert über die parallele Eskalation beider Driver-Mechaniken.
  - **Beat 1:** Letzte große B-Action — schreibhandwerklich: kinetisch, operativ, AEGIS-zentriert, Do-er-Modus voll.
  - **Beat 2:** A-Decision — schreibhandwerklich: interior, kontemplativ, Kael-zentriert, Be-er-Modus voll. Wechsel des dominanten Storyform-Layers innerhalb des Vortex-Bogens.
  - **Beat 3:** Stille — schreibhandwerklich: minimal, sensorisch, ohne Ereignisse. Kein Driver schiebt.
  - **Beat 4:** B's verzögerter Action-Stroke wird sichtbar als Wärme-Phänomen — Landauer-Hitze als somatischer Filter.
  - **Beat 5:** Auflösung — A bleibt; B wird als gewesen markiert. Übergang zu Kapiteln 37–39 (Konsolidierung in der einzelnen verbliebenen Storyform).

## IV. Per-Chapter Dual-POV-Architektur — Option 3 Hybrid

**Lock-In:** 2026-05-07. Beide Storyforms sind in jedem Kapitel präsent, aber der Modus, wie sie präsent sind, variiert je nach Szene und Akt-Position.

### IV.1 Default-Modus: Hard-Routing per POV

In \~80% der Szenen gilt: **eine Szene = eine dominante Storyform, bestimmt durch den POV.**



|  |  |
| :-: | :-: |
| \*\*POV-Instanz\*\* | \*\*Dominante Storyform\*\* |
| ANP-K1 (Kael, Lex, Alex, Rhys, Selene) — 1.Person | A |
| EPs (Nyx, Kiko, Lia, Isabelle, Moros) — 1.Person | A (Kaels Innenwelt) |
| AEGIS — 3.Person | B |
| Argus (Meta-Kognition) | A, mit Kommentar-Überlagerung |
| Juna-POV (selten, Erscheinungsmodi offen) | A |
| Spiegel-Alters (Silas, Oblivion) | wechselnd, je nach welche Spiegelseite gerade dominiert — siehe Bridge-Szenen |



In Default-Szenen ist *nur* die zugeordnete Storyform aktiv. Lesersteuerung-Prinzip "max 1 Konzept pro Szene" wird respektiert. Die Polyphonie zwischen den Storyforms entsteht **zwischen** den Szenen innerhalb eines Kapitels.

### IV.2 Bridge-Szenen: Soft-Layering

Bestimmte Szenen tragen *beide* Storyforms simultan — eine dominant, eine resonant. Bridge-Szenen-Typen:



1.  **Spiegel-Alter-Szenen (Silas, Oblivion).** Diese Charaktere sind ontologisch Doppelfiguren (Silas=Coheron-Echo, Oblivion=Erason-Operator). In ihren POV-Szenen ist beide Storyform-Lesart simultan wahr — die natürliche Heimat des Doppelklangs.
2.  **Riss-Szenen.** Strukturelle Risse in der Simulation sind ontologische Schnittstellen, an denen K0 in K1 einbricht. Schreibhandwerklich: Soft-Layering wird hier durch sensorische Brüche und Tempus-Verschiebungen markiert.
3.  **Vortex-Vorläufer (ab \~Kap 28).** Akt III Anfang. Eskalierende Bridge-Frequenz, vorbereitend auf den Vortex.
4.  **Genesis-Flashbacks.** Akt II Mitte (KW2-KW3-Phase). Die Juna-Wahrheit kollidiert mit der AEGIS-Wahrheit in derselben Szene.
5.  **Vortex (Kap 35–36).** Vollständiges Soft-Layering, beide Storyforms maximal aktiv parallel, bis B in Beat 5 erlischt.



**Mikrocue-Kit für Soft-Layering** (zur Encoding-Disziplin):



  - **Sensorik-Shifts mitten im Absatz** — Kaels warme Kontemplation kippt für einen Atemzug in AEGIS-Kühle und zurück
  - **Syntax-Brüche** — Lex' hypotaktischer Fluss von einem K0-Stiletto-Satz unterbrochen
  - **Footnote-Disruption** — Kael-Szene mit Footnote, die aus B-Lesart denselben Moment rekonstruiert
  - **Tempus-Verschiebungen** — Präsens kippt für drei Worte ins Plusquamperfekt-AEGIS-Protokoll-Register
  - **Kursive Einschübe** — anderer Driver-Pulse hörbar als visuelle Markierung



Disziplin: Mikrocues nur in Bridge-Szenen, nicht in Default-Szenen einschleichen lassen.

### IV.3 Akt-Progression der Bridge-Frequenz

|  |  |  |  |
| :-: | :-: | :-: | :-: |
| \*\*Akt\*\* | \*\*Kapitelbereich\*\* | \*\*Bridge-Anteil\*\* | \*\*Funktion\*\* |
| \*\*Akt I\*\* | Kap 1–13 | \\\~10% (sehr selten) | Etablierung der Storyforms in ihrer reinen Form. Multiplizitäts-Schleier hält. Juna-Seed über Riss-Szenen. |
| \*\*Akt II\*\* | Kap 14–26 | \\\~25% (einzelne Bridges) | Erste Kollision der Wahrheiten. Genesis-Flashbacks als Bridge-Cluster. |
| \*\*Akt III\*\* | Kap 27–34 | \\\~40% (häufige Bridges) | Vortex-Vorläufer eskalieren. Spiegel-Alters intensivieren. FM-Achievement Kap 33. |
| \*\*Vortex\*\* | Kap 35–36 | 100% (full Soft-Layering) | Beide Storyforms maximal simultan, dann Übergang B→A. |
| \*\*Resolution\*\* | Kap 37–39 | 0% (nur A aktiv) | B ist beendet. Konsolidierung in der einzelnen verbliebenen Storyform. |



Diese Progression macht die Polyphonie-Akt-Struktur (fragmentiert → Übergang → chorisch) zur Mechanik, nicht zur Stilanweisung.

### IV.4 Encoding-Implikationen

**Default-Szene encoden:** Den Storyform-spezifischen Storypoint in der Szene umsetzen (welcher Concern? welches Issue? welches Problem-Element?), Sensorik und Syntax dem Storyform-Stil anpassen (siehe alter-spezifische Stilcodes), keine Mikrocues der anderen Storyform einschleusen.



**Bridge-Szene encoden:** Beide Storyform-Storypoints in der Szene aktiv halten, dominanten klar dominant, resonanten durch genau einen oder zwei der Mikrocue-Typen. Disziplin: Soft-Layering ist *gezielt*, nicht durchgängig. Pro Bridge-Szene maximal drei Mikrocue-Punkte, sonst kippt die Szene in Mudding.



**Review-Kriterium:** Nach jeder Bridge-Szene check — wären beide Storyforms hier identifizierbar, wenn man nur diese eine Szene läse? Wenn ja: gut. Wenn nur eine identifizierbar wäre: Mikrocue zu schwach. Wenn beide aufdringlich: zu viel, eine zurücknehmen.
