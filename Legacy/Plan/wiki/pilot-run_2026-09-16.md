# Pilot run — BatchCompile live on three documents, 2026-09-16

The first live run of `/research-ingest` (step 4 of the order of work,
`integration-plan_2026-09-15.md` §6). Three documents, chosen because two of
them disagree about how many Alters System Kael has — the contradiction this
wiki exists to surface.

Run artifact: `tools/kpwiki/eval_runs/pilot-2026-09-16.json` (git-ignored; the
numbers and the findings below are the committed record).

## What it cost

| | |
|---|---|
| sources | 3 (245 lines, 26,760 chars) |
| LM calls | 53 (3 triage, 3 extract, 1 plan, 46 merge, 0 decide) |
| wall time | 54 min |
| output tokens | 345,762 |
| cost | $8.38 |
| backend | `claude-cli`, `claude/sonnet`, one process per call |

Per source that is **$2.79 and 18 minutes**, and the merge calls dominate: 46
of 53 calls. Extrapolated to the 23 unique documents of the exported pilot
slice the same settings would cost roughly **$64 and 7 hours**.

The three slowest calls were an extraction (257 s, 28k output tokens) and two
more extractions around 190 s. A large typed output on the CLI backend is
minutes, not seconds, exactly as `docs/dspy-base.md` records.

**This is the number the author decides on.** Three levers exist before
running the rest: the `worker` model for the merge step, fewer concepts per
batch, and `dspy.RLM` for the long documents instead of one extraction call
over the whole body.

141 claims, **0 unassigned**, clustered into 46 concepts, then 49 candidate

The 46 concepts read like the project's own vocabulary: `aegis`, `kael`,

`landauer-prinzip`, `nichts-rauschen`, `risse`, `tsdp`, `anp-ep-phobie`,

### The contradiction it was sent to find

One concept came back `contradicted`: **`die-13-alter`**, with two
disagreements, three sources each, one position per source and a citation per
position. One is `pending`. The other the run marked `supersedes` — and that
turned out to be a defect in the instructions rather than a judgement worth
keeping; see *What the audit found* below.

- *Total number of entities in the canonical Alter-Register (11 vs. 13)* —
  one report standardises to 13 by merging Silas into Rhys and downgrading
  Oblivion, one confirms 11 (Kael plus ten) and calls Silas and Oblivion
  unconfirmed legacy redundancies, and the Hard-Canon consolidation insists on
  exactly 13 and marks every 11-Alter document deprecated.
- *Whether Silas and Oblivion are distinct Alters or resolved into
  Rhys/Moros* — merged, purged, or retained as four separate entities.

That is the loop doing its job: three documents the author wrote months apart,
an open question, no verdict from the machine. Resolving it is a `/tetraframe`
run and a D-xx decision, not something an ingest may decide.

## What it got wrong, and what changed because of it

The run scored **0.987** on `compile_metric` but the wiki lint found **26
errors** on the written pages. That gap is the finding: the metric was weaker
than the lint, so the program was never told about defects the pipeline would
later refuse. Four changes close it.

| defect | count | where it is now caught |
|---|---|---|
| a term in quotation marks inside a claim or a definition sentence that is not in the lines it cites | 16 | `compile_metric` citations axis (`unverifiable_quotes`), the same rule the lint applies to the written page |
| definition sentence not in English | 4 | already scored; unchanged |
| citation quote that does not resolve | 3 | already scored; unchanged |
| claims written in German from an English source | 1 source | `claims_keep_language`, which now scores both directions (`language_of`) |
| `codex_ref` returned as a bare slug (`risse` instead of `codex:risse`) | 6 | `candidates.codex_ref` prefixes a known slug and drops an unknown one — `codex:` targets are terminal and never auto-created |

The first one is the instructive case. The model wrote a German paraphrase of
an English source and put a German term in quotation marks:

```
- „Rejects data that contradicts its internal model as "noise."“ — AEGIS'
  operationaler Zustand ist Operational Closure: Daten, die dem internen
  Modell widersprechen, werden als "Rauschen" abgelehnt. ^[…:16-16]
```

The citation quote is verbatim and resolves. The claim's own `"Rauschen"`
does not appear in line 16, which is English. Quotation marks promise the
source, so both `ExtractClaims` and `MergeConcept` now say that, and the
metric scores it.

With all four rules in place the same saved run scores **0.987** and names 24
deficits; re-rendering it with the codex fix drops the lint from 26 findings
to 20, all of them the quoting defect the instructions now address.

## What the audit found

A later audit re-ran `compile_metric` against the saved run and checked the
report's own claims. Three things came back.

**The report said "two pending disagreements". One of the two was marked
`supersedes`.** The Hard-Canon document says any 11-Alter document is "to be
marked [DEPRECATED] and archived", and `MergeConcept` said resolution was
pending "unless one source explicitly supersedes the other" — so the model
took the claim and resolved the disagreement. That instruction was wrong.
`compile_metric` computed `contradicted` from *pending* disagreements, so a
concept whose disagreements were all `supersedes` would have been scored as
not contradicted: out of the contested count, out of the health view, out of
the author's review queue. Here a second disagreement kept the page visible by
luck. A source that claims authority over other sources was getting it,
silently, against D-W12 and against the rule that a supersession needs
`/tetraframe`. The signature now says resolution is always pending — an ingest
proposes, it never resolves — and the metric scores `contradicted` from the
presence of a disagreement, not its resolution.

**The metric named 16 quoting defects where the lint named 19.** Two
asymmetries: `_citation_axis` reported only the first loose quote per text,
and `unverifiable_quotes` joined every citation on a line into one span while
the lint requires the fragment to sit inside a *single* citation. Both are
fixed; the metric now names the same 19 fragments the lint does.

**Everything else in this report verified exactly**: 141 claims, 0 unassigned,
46 concepts, 46 `create` decisions, 49 pages, 80 edges, 49 log lines, and the
20 lint findings on the re-rendered candidates.

With the audit's fixes the same saved run scores **0.986** and names **28**
deficits — four more than before, which is the point: the metric had been
quietly scoring defects it could not see.

## Why the candidates are not committed

The 49 drafts carry 20 known citation errors, which would make
`scripts/wiki_lint.py --health` red for the whole repository — the invariant
that makes the health check worth running. They were produced with
instructions we now know were incomplete. The next run, with the tightened
signatures, produces the candidates that get committed and reviewed.
