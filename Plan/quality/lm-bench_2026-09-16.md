## The Free Models Router

Benchmarked separately at **6** attempts rather than 3, because a router's
reliability question is different in kind: it serves a *different underlying
model per call*, so the question is not "can this model hold the schema" but
"does every model it might route to hold the schema". It held on all six, at the
second-fastest median in the whole sweep, at no cost.

Its LiteLLM string is `openrouter/openrouter/free` — the provider prefix plus the
router's own id `openrouter/free`. The single-segment spelling resolves to the
provider but sends the model id `free`, which does not exist.

Two properties argue against using it for every role, independent of its score:

- **GEPA optimizes against a moving target.** The `reflection` role tunes
  instructions for a model that will not necessarily serve the next request.
  Prefer a fixed model there.
- **DSPy keys its cache on the prompt, not on the model that answered**, so a
  cached hit replays whichever model answered first and the router's per-call
  variance becomes invisible. Measure reliability with the cache cleared;
  `scripts/lm_bench.py` forces it off for this reason.

Observed in the live verification run and **not** caught by `ingest_metric`: the
router returned a correct German claim set with correct citations and scored
1.00, but its `triage.summary` came back in English for a German source. The
metric checks the claims' language, not the summary's. A lint proves what is
forbidden is absent; it cannot prove what is required is right.

## What this says

**Five models held the schema perfectly, and two of them are free.**
`nex-n2.5-pro:free` and `dots-3-note-preview:free` returned schema-valid,
fully-scoring predictions on every attempt. For the `worker` role — bulk
sub-steps and LM-as-judge — that is the result worth acting on.

**`ling-3.0-flash` is the standout on the paid side:** perfect score at 24.3 s,
the fastest of the five perfect scorers and roughly a third of `gpt-oss-120b`'s
latency for the same quality.

**The two low scorers failed on quality, not structure.** `granite-4.0-h-micro`
(0.75) and `mistral-nemo` (0.73) emitted valid schemas every time and simply
extracted worse claims. That is the more useful kind of failure: it degrades
visibly rather than crashing, and `ingest_metric` catches it.

**The one partial failure is instructive.** `nemotron-3.5-lightning:free` scored
1.00 when it worked but failed one attempt in three with
`AdapterParseError: LM response cannot be serialized to a JSON object`, and the
response began *"Here's a thinking process:"* — a reasoning model emitting its
chain of thought where a JSON object belongs. This is exactly the failure mode
the benchmark was built to catch, and exactly why `--repeats 1` would have been
worthless: a single lucky attempt would have shown 100 %.

Its 245 s median also disqualifies it independently. That is 10× `ling-3.0-flash`
for the same score.

## Caveats — read before acting

1. **One program, one small fixture.** `SourceIngest` on a 4-line German note.
   `BatchCompile` has six predictors and a substantially larger merge step; a
   model that holds this schema may still fail there. A good result here means
   *worth a real trial run*, not *safe to adopt*.
2. **n = 3.** A 100 % structure rate over three attempts is not a reliability
   guarantee. `nemotron-3.5-lightning` would have shown 100 % on the right single
   attempt.
3. **`cost: n/a` does not mean free.** It means LiteLLM has no price table for
   that model. `ling-3.0-flash` and `granite-4.0-h-micro` are paid models whose
   real cost is unmeasured here; only the `:free` rows are genuinely zero.
4. **One response was truncated** at `max_tokens=16000` (`TASK_MAX_TOKENS`).
   Verbose reasoning models may need more headroom than the current ceiling for
   the larger programs.
5. **Latency is high across the board** — 24–74 s for the good models. These
   suit bulk and batch work, not an interactive loop.

## Where OpenRouter actually belongs (author decision, 2026-09-16)

The author's rule: **use OpenRouter only where no DSPy program, and therefore no
typed schema, is at stake.** Measured against the repository, that rule has
almost no surface to land on — `CLAUDE.md`'s "every LLM step is a DSPy program"
is accurate. Grepping every LLM-touching file outside `tools/kpwiki/` returns
three: two setup scripts and `scripts/lm_bench.py` itself.

**The single real candidate is `scripts/lit_critic_gate.py`** — the prose gate.
It reviews German prose in free text with no schema and no enum, which is
exactly the low-risk shape. It is also, per the concept document §3, the gate
that could not run at all in this checkout; `scripts/setup_lit_critic.sh` has
now been run, so it can.

lit-critic knows two providers (`anthropic`, `openai`) and passes no `base_url`
to the client. But the OpenAI SDK reads `OPENAI_BASE_URL` from the environment,
so OpenRouter reaches it **without patching the vendored tool** —
verified live against `.lit-critic-src/.venv` (openai SDK 3.14.1).

**And a caveat that argues against the *router* specifically here.** Three
consecutive identical calls through `openrouter/free` were each served by a
different model, and some of them are reasoning models whose chain of thought is
billed against `max_tokens`:

| `max_tokens` | result | reasoning tokens | served by |
|---:|---|---:|---|
| 400 | **`content: None`**, `finish_reason=length` | 400 | `poolside/laguna-s-2.1:free` |
| 4096 | correct German | 370 | `dots-studio/dots-3-note-preview:free` |
| 16000 | correct German | 25 | `nex-agi/nex-n2.5-pro:free` |

lit-critic hardcodes `max_tokens: 4096` for its openai models. That sufficed in
the measured run, but the reasoning overhead is unbounded and varied 16-fold
across three calls — a longer-reasoning model returns **empty content with no
error**, which a prose gate would read as "nothing to report". For this surface a
fixed cheap model is safer than the router.

Note this failure is invisible to the DSPy benchmark above, which scored the
router at 100 %: `TASK_MAX_TOKENS` is 16,000 there, enough for the reasoning to
finish. The same model is reliable at one token ceiling and silently empty at
another.
