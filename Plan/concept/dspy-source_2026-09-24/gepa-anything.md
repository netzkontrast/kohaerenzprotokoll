**What this part of GEPA is, in 5 lines**: `optimize_anything` is GEPA's API for evolving a
bare `str`/`dict[str,str]` text artifact with no DSPy program underneath — the mechanism this
project calls "job 4". `gskill` is the one real, heavy, end-to-end worked example of exactly
this shape (SWE-bench-style bug-fixing skills), and it is a completely different animal from
what job 4 needs — it evolves skill *content*, not routing *descriptions*, against a
synthetic, Docker-heavy benchmark this repository has no analogue of. The six named adapters
(confidence, MCP, RAG, LangChain, terminal-bench, AnyMaths) are **not** built on
`optimize_anything` at all — every one of them is a hand-written `GEPAAdapter` used with the
older, lower-level `gepa.optimize()` function, which has a different (flat-kwarg) call shape
and, in several places, different defaults than `optimize_anything`'s nested config. GEPA
ships no code that calls the `claude` CLI as a proposer; that is a documentation recipe only,
and it is markedly less careful than this repository's own `scripts/claude_lm.py`.

- **The `LogContext`/`oa.log()` mechanism** — `gepa.optimize_anything.log(*args, sep=" ", end="\n")` writes into a thread-local, per-evaluator-call `LogContext` (an `io.StringIO` behind a lock), drained after the call and merged into `side_info["log"]`. def score(self, is_correct: bool, logprob_score: float | None) -> float:
    if not is_correct:

    if logprob_score is None:

    probability = math.exp(logprob_score)
    if probability >= self.low_confidence_threshold:

    t = probability / self.low_confidence_threshold
    return self.min_score_on_correct + (1.0 - self.min_score_on_correct) * t

## 6. Ten things the skill must say

1. `optimize_anything`'s config surface has ~40 undocumented fields across five dataclasses
   (`EngineConfig` 20, `ReflectionConfig` 9, `MergeConfig` 2, `RefinerConfig` 2, `TrackingConfig`
   11) — the skill's current `surface` block shows 9. See `## API`.
2. `opt_state` is a second reserved-parameter-name trap, identical in shape to `example` but
   with **no loud failure mode at all** — a typo is silently unpopulated forever. See `## API`, `## TEST`.
3. The refiner (`RefinerConfig`) is a whole undocumented mechanism: it auto-injects a
   `refiner_prompt` component, boosts a candidate's *reported score* with a per-evaluation
   LLM rewrite, and hides that boost from the reflective dataset for every component except
   `refiner_prompt` itself. See `## OPT`.
4. `gepa.optimize()` (the older, adapter-based API every one of the six named adapters actually
   uses) and `optimize_anything()` are not just differently shaped — four of their defaults
   for the same setting genuinely disagree (`skip_perfect_score`, `perfect_score`,
   `use_cloudpickle`, `frontier_type`). See `## API`.
5. **gskill optimizes a skill's body text, never its `description:` field** — job 4's actual
   target is untouched by gskill's own reference implementation, and gskill's dataset (hundreds
   of SWE-smith bug-fix instances, Docker required) does not transfer to "5–20 recorded routing
   failures" in any way beyond sharing the `optimize_anything` call shape. See `## SKILL`.
6. GEPA ships no code that calls `claude`; `claude-cli-as-proposer.md` is a documentation
   recipe only, and it is meaningfully less careful than this repository's own
   `scripts/claude_lm.py` on six concrete points — prompt delivery, working directory/`CLAUDE.md`
   discovery, environment scrubbing, tool/session isolation, structured cost/error capture, and
   default thinking budget. Running the doc's own snippet from inside this container would load
   this project's `CLAUDE.md` into every reflection call. See `## SKILL`.
7. `ExecutionMode.IN_PROCESS` (the default for `utils/code_execution.py`) runs untrusted
   candidate code with `exec()` in the same process as GEPA, and its `SIGALRM` timeout crashes
   outright when called from any thread but the main one — exactly where GEPA's default
   `parallel=True` runs evaluator calls. See `## PROD`.
8. Caching of evaluations (`cache_evaluation`, `cache_evaluation_storage`) is a real, tested,
   three-way resolution (`off`/`memory`/`disk`, `disk` requiring `run_dir`) with a concrete
   trap: the cache key falls back to Python's `id()` — not stable across processes — for any
   `example` that is not JSON-serializable. See `## API`, `## TRAP`.
9. GEPA's own adapters disagree on what an exception means: `EvaluatorWrapper` respects
   `raise_on_exception`; `MCPAdapter`/`GenericRAGAdapter` never raise regardless of it;
   `LangChainAdapter` turns the exception into data and defers the score to the caller's own
   `eval_fn`. A job-4 evaluator should pick one of these deliberately, not inherit one by
   accident. See `## PAT`.
10. `docs/docs/api/**/*.md` are bare `mkdocstrings` stubs with `show_source: true` and zero
    independent prose — reading the `.py` source *is* reading the docs for this slice; two
    genuinely separate documents (`adapters/README.md` and the `adapters.md` guide) each
    under-list the real adapter catalogue, and `GEPA_RAG.md` calls a parameter
    (`reflection_llm_model`) that does not exist on `gepa.optimize()`. See `## TRAP`.
