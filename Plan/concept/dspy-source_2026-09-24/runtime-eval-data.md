**What this part of DSPy is, in five lines.** `dspy.Evaluate` runs a program over a devset through the same
`ParallelExecutor` that backs `dspy.Parallel` and `Module.batch`, turns a metric's `bool`/`float`/`Prediction`
return into one aggregate score, and — this is the load-bearing fact for this repository — silently folds
every metric exception and every execution failure into `failure_score` (default `0.0`), indistinguishable in
`.results` from a genuinely low score. `dspy/evaluate/metrics.py` ships English-only string metrics;
`auto_evaluation.py` ships two LM-judge `Module`s that switch between a float and a bool based on whether
`trace` is set. `dspy/datasets/` is four unrelated dataset loaders wearing one `Dataset` base class inconsistently.
`dspy/utils/` supplies the plumbing all of this depends on: a callback system with call-id parenting across
thread boundaries, a thread pool that records failures it never gets asked for, and structured, HTTP-metadata-
carrying exceptions.

## 2. Knowledge items

### API

- **`Evaluate.__init__` is keyword-only after `self`** — `devset` has no default and every other parameter does; passing `return_outputs=` in `**kwargs` raises `ValueError("`return_outputs` is no longer supported. Results are always returned inside the `results` field of the `EvaluationResult` object.")`. `dspy/evaluate/evaluate.py:71-114` [api] (verified: `inspect.signature`) · skill: same (`api.md:73`; the removed-kwarg guard is new detail).
- **`Evaluate.__call__` cannot override `max_errors`, `failure_score` or `provide_traceback` per call** — only `program`, `metric`, `devset`, `num_threads`, `display_progress`, `display_table`, `callback_metadata`, `save_as_csv`, `save_as_json` are call-level; the other three live only on `self`, fixed at construction. `dspy/evaluate/evaluate.py:116-128` [api] (verified: `inspect.signature` on `Evaluate.__call__`) · skill: new.
- **`callback_metadata` is call-only, and does nothing but log** — it is never stored on `self`, its only use is `logger.debug(f"Evaluate is called with callback metadata: {callback_metadata}")` and it is *not* forwarded to the callback's `inputs` dict — a callback sees it only if it separately inspects `Evaluate.__call__`'s bound args via `inputs["callback_metadata"]`, which `with_callbacks` does build from `inspect.getcallargs`. `dspy/evaluate/evaluate.py:125,157-158` [api] (verified: read + `test_evaluate_callback` shows `callback.start_call_inputs["program"]`, confirming `inputs` is the full call-args dict) · skill: new.
- **`Evaluate` clears the global tqdm registry before every run** — `tqdm.tqdm._instances.clear()` runs once in `Evaluate.__call__` (`evaluate.py:160`) and again inside `ParallelExecutor.execute` (`parallelizer.py:51`) — redundant but harmless; the second clear means a bar from an *unrelated* concurrent tqdm use elsewhere in the process can be wiped by an `Evaluate` call. `dspy/evaluate/evaluate.py:160`, `dspy/utils/parallelizer.py:51` [trap] (verified: read) · skill: new.
- **`process_item`, the exact metric call site** — `prediction = program(**example.inputs()); score = metric(example, prediction)` — two positional arguments, nothing else, confirming `Evaluate` never passes `trace`, `pred_name` or `pred_trace`. `dspy/evaluate/evaluate.py:170-173` [api] (verified: read) · skill: same (`api.md:473-476`).
- **A failed or cancelled item becomes `(dspy.Prediction(), self.failure_score)`** — `results = [((dspy.Prediction(), self.failure_score) if r is None else r) for r in results]`; `dspy.Prediction()` is empty (no fields), so `.results`' second tuple element for a failure is indistinguishable in shape from a genuinely empty prediction. `dspy/evaluate/evaluate.py:178` [api|trap] (verified: probe `p_evaluate_failure_score_hides_exception`, §4) · skill: unchecked (`api.md:450-453` states the score consequence but not that the *prediction* itself becomes a bare empty `Prediction`, or that this is the exact line).
- **The final score line divides even when the result is about to be zero** — `ncorrect, ntotal = sum(score for *_, score in results), len(devset)`; `logger.info(f"Average Metric: {ncorrect} / {ntotal} ({round(100 * ncorrect / ntotal, 1)}%)")` runs *before* `display_table`/`save_as_csv`/`save_as_json`, so an empty `devset` raises `ZeroDivisionError` at this line, not later. `dspy/evaluate/evaluate.py:180-182` [api] (verified: read) · skill: same, more precise (`api.md:468-470` names the effect, not the line).
- **`display_table` needs pandas; its absence is a warning, not a crash** — `importlib.util.find_spec("pandas") is None` → `logger.warning("Skipping table display since \`pandas\` is not installed.")`; in `.venv-dspy` here, pandas is **not installed**, so `display_table=True` silently does nothing but warn. `dspy/evaluate/evaluate.py:184-193` [api] (verified: `env -u ... .venv-dspy/bin/python -c "import pandas"` → `ModuleNotFoundError`) · skill: new.
- **`save_as_csv` is written before `save_as_json`, and only the JSON path can crash on a `Prediction`-shaped score** — `csv.DictWriter` stringifies any cell including a `dspy.Prediction`; `json.dump` cannot. If both are set and the metric returns `Prediction(score, feedback)`, the CSV file is written successfully and *then* `save_as_json` raises. Neither call creates its parent directory (`open(path, "w")` with no `os.makedirs`). `dspy/evaluate/evaluate.py:195-221` [api|trap] (verified: read) · skill: unchecked (`api.md:462-465` has the JSON crash `[checked: save-as-json-prediction-crashes]` but not that CSV, written first, survives the exact same score value).
- **`_prepare_results_output` renames on collision, keeps the bare name otherwise** — for a dict-like prediction, `merge_dicts(example, prediction)` prefixes a field with `example_`/`pred_` **only when both sides share that key**; a field unique to one side keeps its bare name. For a non-dict-like prediction (e.g. a program returning a bare list via `.entities`), the row is `example.toDict() | {"prediction": prediction, metric_name: score}` — the whole prediction sits under the literal key `"prediction"`. `dspy/evaluate/evaluate.py:228-239,301-327` [api] (verified: DSPy's own `test_construct_result_df`, `tests/evaluate/test_evaluate.py:87-114`, exact columns `question, example_answer, pred_answer, answer_exact_match`) · skill: new.

**`_bind_active_call_id` — the whole mechanism that makes callback call-ids parent correctly across threads** (`dspy/utils/callback_context.py:1-20`, ran on the installed package via probe §4):
```python
import functools
from contextvars import ContextVar
from typing import Callable

ACTIVE_CALL_ID = ContextVar("active_call_id", default=None)
_ACTIVE_COMPILES = ContextVar("active_compiles", default=())


def _bind_active_call_id(fn: Callable) -> Callable:
    """Bind the current callback call ID to each synchronous invocation of ``fn``."""
    parent_call_id = ACTIVE_CALL_ID.get()

    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        token = ACTIVE_CALL_ID.set(parent_call_id)
        try:
            return fn(*args, **kwargs)
        finally:
            ACTIVE_CALL_ID.reset(token)

    return wrapper
```

**`ParallelExecutor._wrap_function` — how a caught exception becomes a value, and how `max_errors` actually fires** (`dspy/utils/parallelizer.py:57-74`, read on the installed package):
```python
def _wrap_function(self, user_function):
    def safe_func(item):
        if self.cancel_jobs.is_set():
            return None
        try:
            return user_function(item)
        except Exception as e:
            with self.error_lock:
                self.error_count += 1
                if self.error_count >= self.max_errors:
                    self.cancel_jobs.set()
            if self.provide_traceback:
                logger.error(f"Error for {item}: {e}\n{traceback.format_exc()}")
            else:
                logger.error(f"Error for {item}: {e}. Set `provide_traceback=True` for traceback.")
            return e

    return safe_func
```

**`callback-call-id-parenting`** — "Every module call inside a running module's `forward` reports `ACTIVE_CALL_ID.get()` equal to the enclosing call's own `call_id`; a top-level call sees `None`."
```python
def p_callback_call_id_parenting():
    import dspy
    from dspy.utils.callback import ACTIVE_CALL_ID, BaseCallback

    class Recorder(BaseCallback):
        def __init__(self):
            self.parents = []
            self.ids = []
        def on_module_start(self, call_id, instance, inputs):
            self.parents.append(ACTIVE_CALL_ID.get())
            self.ids.append(call_id)

    class Child(dspy.Module):
        def forward(self):
            return None

    class Parent(dspy.Module):
        def __init__(self):
            super().__init__()
            self.c1 = Child()
            self.c2 = Child()
        def forward(self):
            self.c1()
            self.c2()

    cb = Recorder()
    dspy.configure(callbacks=[cb])
    Parent()()
    if len(set(cb.ids)) != 3:
        return f"expected 3 distinct call_ids, got {cb.ids}"
    if cb.parents != [None, cb.ids[0], cb.ids[0]]:
        return f"expected [None, parent, parent], got {cb.parents}"
    return None
```

## 6. Ten things the skill must say

1. `operations.md`'s pointer to `api.md` for "the full `BaseCallback` hook list" is false — nothing in the map documents callbacks at all; `dspy/utils/callback.py` needs its own coverage (16 hook pairs, dispatch order, call-id parenting).
2. `Evaluate.__call__` discards `ParallelExecutor`'s own `.failed_indices`/`.exceptions_map` after every run — the real exception objects exist for one call, then vanish; `EvaluationResult` records only an empty `Prediction()` at `failure_score` where an exception happened (§2 API, §4 probes).
3. The official docs (`diving-deeper/metrics-and-evaluation.md:43-45`) present `Evaluate`'s exception-to-`failure_score` folding as a deliberate benefit — the exact opposite of this repository's P15, stated as upstream design intent, not an oversight.
4. `dspy.evaluate.answer_exact_match_str` does not exist and is taught by the official docs (`learn/evaluation/metrics.md:139`) and by dead test code in the same repository (`tests/examples/test_baleen.py:82`) — verified `False` by `hasattr` against the installed package, twice.
5. `SemanticF1`/`CompleteAndGrounded` are real LM judges (one or two `ChainOfThought` calls each, per scored example) with two different field conventions from `answer_exact_match` (`.response`/`.question` vs `.answer`) and from each other's neighbor `answer_passage_match` (`pred.context` as `str` vs `list[str]`).
6. `normalize_text`, and therefore `EM`/`F1`/`answer_exact_match`, only strips English articles and ASCII punctuation — silently under-normalizes German text, worth flagging for a German-corpus project even though nothing here uses it yet.
7. `dspy.datasets`' four bundled loaders (`HotPotQA`, `GSM8K`, `MATH`, `AlfWorld`) all need the `datasets` package, which is a `test_extras`-only dependency **not installed** in `.venv-dspy` here; only `Colors` (no network, no optional dependency) works as-is.
8. `ParallelExecutor` with `num_threads=1` runs on the calling thread with no `ThreadPoolExecutor` at all — this, not merely "fewer threads", is why `track_usage()` only works correctly at `num_threads=1`.
9. `syncify`'s fallback for calling into an already-running event loop needs `nest_asyncio`, which is not declared anywhere in `pyproject.toml` and is not installed here — a documented, supported code path that can raise `ModuleNotFoundError`.
10. `Evaluate.__init__`'s removed-kwarg guard only checks `return_outputs`; the docs claim `return_all_scores` also raises, but passing it is silently absorbed into `**kwargs` and ignored.
