**What this part of DSPy/GEPA is, in 5 lines**: `dspy.GEPA` is a thin, DSPy-shaped skin over `gepa.optimize()` (the GEPA 0.1.4 package's one public entry point): it builds a `DspyAdapter` that turns a DSPy module into a `dict[str, str]` candidate (predictor name → instruction text, or `dspy.Flex` path → full module source), and calls `optimize()` with that adapter, a five-argument feedback metric, and a translated budget. GEPA's engine repeats: sample a Pareto-front candidate, sample a minibatch, evaluate, build a reflective dataset, call a reflection LM to rewrite one (or more) component, accept if the minibatch score improved, occasionally merge two candidates' components. Every extension point — which candidate to mutate, which component, how many proposals per iteration, when to stop, where metrics go — is a small strategy object with one or two built-ins and a documented protocol for a custom one. Cost/token tracking exists in the package but is architecturally inert for `dspy.GEPA`, because DSPy hands it a bare Python callable, not a `gepa.lm.LM`.

```python
# gepa:src/gepa/gepa_utils.py:90-117 (select_program_candidate_from_pareto_front)
def select_program_candidate_from_pareto_front(
    pareto_front_programs: Mapping[Any, set[int]],
    train_val_weighted_agg_scores_for_all_programs: list[float],
    rng: random.Random,
) -> int:
    train_val_pareto_front_programs = pareto_front_programs
    new_program_at_pareto_front_valset = remove_dominated_programs(
        train_val_pareto_front_programs, scores=train_val_weighted_agg_scores_for_all_programs
    )
    program_frequency_in_validation_pareto_front = {}
    for testcase_pareto_front in new_program_at_pareto_front_valset.values():
        for prog_idx in testcase_pareto_front:
            if prog_idx not in program_frequency_in_validation_pareto_front:
                program_frequency_in_validation_pareto_front[prog_idx] = 0
            program_frequency_in_validation_pareto_front[prog_idx] += 1

    sampling_list = [
        prog_idx for prog_idx, freq in program_frequency_in_validation_pareto_front.items() for _ in range(freq)
    ]
    assert len(sampling_list) > 0
    curr_prog_id = rng.choice(sampling_list)
    return curr_prog_id
```

## 6. Ten things the skill must say

1. `gepa_kwargs` reaches `gepa.optimize()`'s *closed* keyword list (no `**kwargs`) only at `.compile()` time, not at `dspy.GEPA(...)` construction — a bad key (e.g. `enable_tool_optimization`, which belongs only to GEPA's own stale vendored adapter) raises `TypeError` only once you call `.compile()`. — TRAP, `dspy/teleprompt/gepa/gepa.py:661`, `gepa:src/gepa/api.py:46-103`
2. `dspy.GEPA`'s reflection cost is always invisible: it hands `gepa.optimize()` a bare callable, which gets wrapped in `TrackingLM` and reports `total_cost == 0.0` forever; `max_reflection_cost` is explicitly rejected for exactly this reason, and even a raw `gepa.optimize()` caller has no return path back to the wrapper object. — TRAP, `gepa:src/gepa/lm.py:190-236`
3. `gepa_kwargs={"stop_callbacks": [...]}` does **not** override the ever-present `max_metric_calls` stopper as `dspy.GEPA`'s own docstring claims — both combine in a `CompositeStopper(mode="any")`, first-to-fire wins. — TRAP, `gepa:src/gepa/api.py:252-295`
4. The exact default reflection prompt text (`<curr_param>`/`<side_info>` template) is quotable verbatim and is what every non-custom-proposer `dspy.GEPA` reflection call sends. — API, `gepa:src/gepa/strategies/instruction_proposal.py:13-29`
5. With the default instruction proposer, a `dspy.Image` (or any `dspy.Type`) input is silently `str()`-ified in the reflective dataset unless `instruction_proposer=MultiModalInstructionProposer()` is set — confirmed by two dedicated DSPy tests asserting the serialized/structured split. — TRAP, `dspy/teleprompt/gepa/gepa_utils.py:390-394`
6. `use_merge=True` is `dspy.GEPA`'s own default, flipping GEPA's package default of `False`; the merge algorithm requires a common ancestor that scores no higher than either of two Pareto-dominating descendants, and only accepts a merge that beats both parents. — OPT, `dspy/teleprompt/gepa/gepa.py:396`, `gepa:src/gepa/proposer/merge.py:27-207`
7. Candidate selection is a frequency-weighted sample over *dominators* of the per-key Pareto front, not true multi-objective non-domination — a candidate that is merely competitive but never best-on-any-key is permanently excluded from `"pareto"` selection. — OPT, `gepa:src/gepa/gepa_utils.py:23-118`
8. `auto="light"/"medium"/"heavy"` translates to an exact metric-call budget via a closed formula, checked at two different predictor counts against both this repository's own live log and GEPA's published doc example. — OPT/number, `dspy/teleprompt/gepa/gepa.py:490-520`
9. `dspy.GEPA` exposes no `callbacks=` of its own (only via `gepa_kwargs`) — the 22-event `GEPACallback` protocol (not 21, per a stale guide count) is where per-reflection-call prompts/raw-outputs, budget deltas, and Pareto-front changes are actually observable, and the `on_iteration_start` event's `trainset_loader` is the one field GEPA itself calls out as safe to mutate. — API/PROD, `gepa:src/gepa/core/callbacks.py`
10. When `run_dir` is set, resuming is automatic (same directory → same `gepa_state.bin` loaded) and a second call with `max_metric_calls=0` returns the prior run's exact totals; the directory also holds `run_log.json`, `candidates.json`, `candidate_tree.html`, and an auto-registered `gepa.stop` file a person can `touch` to end the run gracefully. — PROD, `gepa:src/gepa/core/state.py:299-347`, `gepa:src/gepa/api.py:260-261`
