**The check column is the heavy one, and that is the right order** — you cannot
automate what you cannot verify. But it means every step that *produces* content
is still a person, and that is the problem below.

**New capability, verified rather than assumed:** an LM can run here. Deno
installed, dspy 3.3.1, the `ClaudeLM` bridge (no API key), an OpenRouter key, and
32 DSPy skills. Measured: a free model beat `fold()` on the near-match task,
94% against 65%. **The baseline has since moved to
60 <!--state:trainset.fold_baseline_pct-->%** — each new reconciliation adds
judgements, most of them plurals, inflections or slashes, which is what
`fold()` does not do. The gap is wider than it was and the reason is the same one
as before: the misses are systematic, so the next improvement is still a rule.

## The three facts that decide everything

**1. Four of 346 documents. Hand-rate does not finish.**
That is 1.1%, after two sessions. Nothing in the plan matters more than this.

**2. Term extraction has 5 <!--state:trainset.gold_candidate_lists--> gold
examples.** The first four candidate lists are *reconstructions* written after
the counts; every document read since document 5 was written during the read
and is genuine. It is the one artifact a program cannot produce, it is what any
automated extractor must be scored against, and **the first four documents
cannot be repaired — only outgrown.** Five of nine documents with a census, and
the rate is now one per document.

**3. The wiki is terms with too few relations.**
59 <!--state:wiki.pages--> pages, 283 <!--state:wiki.relations--> links between
them, 16 <!--state:wiki.orphans--> orphans.

*Corrected 2026-09-17:* this read „almost no relations — 48 links, 22 orphans",
which counted the cross-references written in backticks. Decision 005 gave a link
its own syntax and marked the ones the prose already made.

Document 6 then raised the count again from a single reconciliation, because a
gazetteer's pages name the level, the bearer and the neighbours of every place —
the first evidence that **relations arrive with a document's shape rather than
being harvested from pages that already have them**.

The point survives both: the three hardest open problems are all *relation*
questions — Q1 how the Guardians relate to AEGIS, J18 whether `Nexus`
and `Überraum` are one space, J13 what the corpus calls the Kael–Julia bond.
`account()` has subjects for a document, a term, a pair, the corpus and the
pipeline's order — and **none for a relation**, which is why all three had to be
argued in prose.

## The idea that changes the sequencing

`Wiki/questions/` was created today because 70 open statements were sitting
inert on 33 pages, 24 of them repeats of each other. There are now
126 <!--state:wiki.open_statements-->.
It is not only a place to park them.

**The questions are the evaluation set, and they need no labelling.**

*Can the wiki answer Q1 yet?* is a question a program can ask, the questions are
already written, already attributed, already in the corpus's own German terms,
and they accumulate for free as a byproduct of reading documents. That is exactly
the loop `dspy-deep-refine` describes — unanswerable questions become reviewed
edits — and this project has been generating its input for weeks without using it.

It also replaces a guess with a measurement: **which document to read next is
whichever one closes the most open questions.** C4 already did this by hand for
document 5. `qmd.py` can now do it for all of them.

## The plan

Four phases. Each gate is a **measurement**, not a checkbox — `state.py --get`
answers it, so no phase can be declared done by assertion.

### Phase A — make the next document produce gold

The unblock. Two things, in this order:

1. **Decide the near-copy rule.** Document 5 has four landed near-copies
   (`duplicates.py --groups`). Which one is read, and why, and where that is
   recorded. No precedent exists. It applies to 52 files, so it is not a detail.
2. **Read `aegis-subplots-kapitelweise-system-exploration-docx` end to end**, with the
   candidate list written *while reading and before any counting*. `capture.py`
   already refuses to count without one; the discipline is to not work around it.

It should close **Q1**, which is the first time a document is chosen by a
question rather than by category order.

> **Gate:** `trainset.gold_candidate_lists` ≥ 1, `wiki.questions` answered ≥ 1.

### Phase B — the extraction baseline, before any model

Same discipline that produced `fold()`'s 82%. The surface index already exists:
**what does a purely deterministic extractor score against a real gold candidate
list?** Precision and recall separately, because they fail for different reasons.

This is free, it needs no LM, and it decides whether Phase C is worth anything.
A model that does not beat it is not worth a call.

> **Gate:** a recorded precision/recall baseline for extraction, in
> `Plan/quality/`, reproducible by one command.

### Phase C — build the gold set to where an optimizer has something to eat

Documents 5 through ~12, **one per category where possible** rather than eight
from one. Categories matter: new terms per document fell 14 → 10 → 8 inside
`theorie-physik` and reset to 14 on the first `worldbuilding` document. There are
12 categories and 346 documents; **the decay curve is measured on three documents
in one category and is the number that decides whether this ever finishes.**

Then, and only then, an LM on extraction — scored against gold, with a held-out
canary, against the Phase B baseline. The canary is not optional: a free model
already tied the baseline's score while merging `Negentropie` with `Entropie`.

> **Gate:** `trainset.gold_candidate_lists` ≥ 8, a measured decay curve across
> ≥ 3 categories, and an extractor that beats Phase B *and* holds its canaries.

### Phase D — promotion, and the rule that does not exist yet

46 candidates and no reviewed layer. `dspy-wiki-compile` names the rule this
project lacks: **a reviewed page is authoritative; conflicting content is flagged
with the conflicts listed, never updated in place.** Decision 003 governs
conflicts *between sources* and says nothing about a source against a human
judgement.

`quotes.py` is already the gate's hard half — a page with an unresolved citation
cannot be promoted. That is 17 <!--state:quotes.unresolved--> pages' worth of
work that is now the highest-value cleanup in the wiki, because an independent
design weights `citations resolve` heaviest of six axes.

> **Gate:** `quotes.unresolved` = 0, a written promotion rule, `Wiki/terms/`
> holding its first page.

## Running alongside

- **`account relation`** — the missing subject. Derive it from what pages already
  say (`relations.py` does), and only then ask whether a model should propose
  edges prose does not state. A guessed edge is indistinguishable from a stated
  one once it is in the graph.
- **The 293 <!--state:quotes.unchecked--> unverifiable quotations.** They carry no
  citation on their own line, usually a table cell whose line number is in
  another column. Either the convention changes or the checker does; nobody has
  decided. Document 6 showed the cheap half of the fix works — putting the
  reference inside the cell took nine new pages from 9 unchecked to 0.
- **J13 and J18.** Both are decisions that would merge or rename pages, which is
  exactly what `dspy-tetraframe` exists for. Neither should be settled casually.

## What this plan does not claim

The decay curve is three data points in one category. The extraction baseline
does not exist yet. 94% against 82% was 16 right against 14 on 17 items with no
held-out split. **Phase C's gate is written the way it is because none of those
numbers is trustworthy yet**, and the plan's job is to make them so, not to
assume them.
