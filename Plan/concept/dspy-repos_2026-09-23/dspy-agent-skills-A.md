## 1. What it is

A pack of ~40 Claude Code / Codex skills teaching agents to build DSPy 3.3.x
programs, plus a pytest suite (633 tests, all offline, 1.36s) that enforces
skill-doc correctness against a specific set of drift bugs the maintainers
actually hit. Every skill ships a runnable `example_*.py --dry-run` (no LM
call, asserted by tests and verified live for one example above) and a
`reference.md` for deep API detail. DSPy target: `dspy>=3.3.0,<3.4`
(`requirements.txt`), matching the target's `.venv-dspy` pin of 3.3.1 exactly.
Maturity: the skill *docs* are unusually well-tested (regression tests named
after specific past mistakes — see §Verdict); the underlying third-party
packages they describe (drg-kg, dspy-refrag, TARA, dspytools, dspy-rlm-hooks)
are separately audited with file:line evidence and are frequently found
broken or overclaimed. This repo is a teaching/reference layer, not a library
to `pip install`; nothing runs against a live LM in this scan.

## 2. Every good idea

### Verification & CI patterns
1. **Live API-surface check as a test, not a doc claim** — `scripts/check_dspy_surface.py:1-204` imports the installed `dspy`, asserts exact version, then walks `inspect.signature` on every API surface the pack teaches (`GEPA`, `BetterTogether`, `Evaluate`, `LM`, `SIMBA`, `Embedder.__call__`, `configure_cache`, `Refine`/`BestOfN`, `RLM`, `ProgramOfThought`, `CodeAct`, `PythonInterpreter`) and fails loudly (`FAIL: ...`, exit 1) the moment a rename lands, plus runs one real `dspy.Evaluate` call to check `.score` aggregation semantics. **[adopt]** — this is exactly P1/P23 ("guard reports what it could NOT check" is the negative space; here it's "guard reports the moment truth changes under it"). Kohärenzprotokoll's `.venv-dspy` pin plus `dspy.RLM` experimental status is the same failure mode this script exists to catch (see §4).
2. **Regression tests named after real incidents, each with its provenance in the docstring** — `tests/test_skill_correctness.py:1-40` states in a block comment *why* each of its 10 rules exists ("we shipped subtly wrong teaching material once and caught it in external review"). **[adopt]** — directly mirrors the target's own practice of writing `Plan/learnings/*.md` per defect; this shows the same idea as *executable* tests instead of prose, e.g. rule 3's stale-default guard is basically what `selftest.py` does for `quotes.py`.
3. **Anti-pattern allowlist via marker words, not exclusion lists** — `_ANTIPATTERN_MARKERS` (`tests/test_skill_correctness.py:82-95`) lets a line legitimately *mention* a banned pattern ("don't do X") without tripping the guard, by requiring one of a fixed set of words nearby. **[adapt]** — kohaerenzprotokoll's own prose is full of intentional "this construct is wrong" callouts (e.g. quoting the false `.overall_score`-style bug pattern in `PRINCIPLES.md`); this pattern is a cheap way to keep a grep-based checker from firing on its own examples.
4. **Frontmatter forbidden-field list, enforced positively** — `tests/test_skill_metadata.py:41` (`FORBIDDEN_FIELDS = {"triggers","version","dspy-compatibility","dspy-version"}`) fails a skill that adds fields the harness silently ignores. **[adopt]** — the target has `.agents/skills/*/SKILL.md` (vendored `jev*` and project skills like `ingest`, `qmd`, `tools`); nothing in the target currently validates their frontmatter against the Claude Code/Codex spec. This test file is close to drop-in.
5. **YAML-strictness guard for `npx skills` compatibility** — `test_frontmatter_plain_scalars_are_yaml_safe` (`tests/test_skill_metadata.py:129-154`) catches an inline scalar containing `": "` that a loose parser tolerates but a strict YAML parser breaks on. **[catalogue]** — narrow but cheap; worth adding once the target's skills grow past hand-checking.
6. **Manifest/version-consistency cross-checks** — `tests/test_manifests.py` checks `plugin.json`/`marketplace.json`/README version strings agree and that plugin entries cross-reference. **[skip]** for the target directly (no plugin manifest concept there) but **[catalogue]** as the general pattern: "N places claim the same number; test that they agree" is literally `scripts/state.py --prose`'s job already, done better (marker-based) in the target.
7. **AST-parse every example/script/scaffold, offline, before anything else** — `tests/test_examples_parse.py:1-54`. **[adopt]** — trivial and catches syntax errors in `Plan/runs/*.py`-style artifacts or any new script before a real test run; cheap to add to the target's own `selftest.py` or a pre-commit hook.
8. **"A scaffold with no plan is dead code" test** — `test_scaffolds_are_documented` (`tests/test_examples_parse.py:56-63`) fails if a file under `scaffolding/` is not named anywhere in `docs/*.md`. **[adapt]** — direct analogue to the target's own rule "a construct is demoted, not deleted" / "no field without real instances" (PRINCIPLES P3/P4): this is the *automatic* version — a Python helper with no citing doc is a smell.
9. **All example scripts require `--dry-run` (tested twice, at parse time and at doc-correctness time)** — enforced by both `test_examples_parse.py` and `test_skill_correctness.py`. **[adopt]** — this is P5 verbatim ("every workflow ships an offline, no-key fixture"). `rlm_ingest.py` in the target has no `--dry-run`; adding one that stubs the RLM/LM construction (per the CLAUDE.md gotcha about `dspy.GEPA`/`MIPROv2` validating LMs at construction, not compile) would let CI catch a broken `briefing()`/`numbered()` call without spending an OpenRouter call.

### GEPA / metric patterns
10. **The exact axis table cited in the brief** — `dspy-wiki-compile/reference.md:56-58` and `SKILL.md:85-91`: weights `{citations: 0.30, decisions: 0.25, merge: 0.20, diffs: 0.15, links+language: 0.10}`, every axis deterministic, feedback strings are literal templates (`"citation does not resolve: {file}:{start}-{end} {quote[:30]!r}"`). Confirmed by reading `example_wiki_compile.py:224-237` (`compile_metric`) and running it: fixture scores 1.0, a deliberately broken fixture scores 0.657 and the feedback contains all four expected deficit strings. **[adopt-as-reference]** — the target's own reconciliation metric (verified/unverified line citations, decision legality) is structurally identical; this file is a clean worked example of "every metric axis is a deterministic function with a feedback string," which the target does not yet have codified for its own eventual `fold()`/reconcile metric.
11. **`decision_legal()` = the "reviewed page is authoritative" rule, exactly as the brief described it** — `example_wiki_compile.py:129-135`: `update` on a page whose `status in PROTECTED_STATUSES` (`reviewed`, `locked`) *with conflicts* is illegal; only `flag` is legal. Confirmed: a bad fixture triggers `"illegal decision: update on juna (status reviewed, conflicts [...])"`. **[adopt]** — maps almost 1:1 onto the target's "a reviewed page is authoritative... conflicting content is flagged, never applied" — except the target doesn't have a `status` field on wiki pages yet (no `draft/reviewed/locked/contested/archived` enum). Worth **[adapt]**ing as a future page-status field, gated by P3/P4 (don't add until there's a real instance of a page being wrongly overwritten).
12. **5-argument metric contract, everywhere, no exceptions** — `dspy-evaluation-harness/SKILL.md:16`, `dspy-gepa-optimizer/SKILL.md:16`, `dspy-optimizer-selection/SKILL.md:116-125`, `scripts/check_dspy_surface.py:174-181`, and three separate tests (`test_skill_correctness.py` rules 1, 2, 9) all converge: `def metric(gold, pred, trace=None, pred_name=None, pred_trace=None) -> dspy.Prediction(score, feedback)`, never a dict (`dspy.Evaluate`'s parallel aggregator does `sum()` and raises `TypeError: unsupported operand type(s) for +: 'int' and 'dict'`). **[adopt]** — this is the single most load-bearing, most repeated fact in the pack. If kohaerenzprotokoll writes any GEPA metric for `fold()`/one-term-or-two, this is the exact contract to start from.
13. **`pred_name`/`pred_trace` for per-predictor blame** — repeated across `dspy-gepa-optimizer` and `dspy-rlm-workflow` (`reference.md:104-106`: "Feedback strings must say which sub-problem or module failed"). **[adopt]** — GEPA can only assign credit to a specific predictor if the metric writes feedback naming it; relevant the moment kohaerenzprotokoll's one-term-or-two program has more than one predictor.
14. **`dspy.GEPA(reflection_lm=...)` asserts at construction, not compile** — called out three times independently (`dspy-gepa-optimizer/SKILL.md:191-199`, `dspy-optimizer-selection/reference.md:104-109`, `CLAUDE.md` gotchas). **[adopt]** — this is exactly why any `--dry-run` path in the target that constructs a `dspy.GEPA` needs a stub `dspy.LM(...)` (free, no network) rather than skipping construction; a direct instruction for writing `rlm_ingest.py --dry-run` or a future `fold_gepa.py --dry-run`.
15. **n≈20-50 "well-chosen beats 500 bland" framing for GEPA** — `dspy-optimizer-selection/reference.md:74-78`: "GEPA is the exception to 'more data is better': it learns from the feedback text of a few dozen informative failures... 20–50 well-chosen examples often beats 500 bland ones." **[adopt]** — matches the target's n=26 surface-pairs dataset almost exactly; this is direct license to try GEPA on `fold()` without waiting to collect more data, addressing the brief's "small data: n=26... say so" instruction with actual matching guidance rather than a generic warning.
16. **Selection matrix + escalation order, stop-at-first-row discipline** — `dspy-optimizer-selection/SKILL.md:40-73`: baseline → LabeledFewShot → BootstrapFewShot → BootstrapRS → (scalar: MIPRO/SIMBA | rich feedback: GEPA) → BootstrapFinetune/BetterTogether, "escalate only on a measured plateau." **[adopt]** — this is precisely the ladder the brief names (LabeledFewShot → BootstrapFewShot → InferRules → SIMBA → GEPA) except this pack's canonical ladder doesn't mention `InferRules` at all (only seen as one of `dspytools`' ten registry optimizers, `dspy-tools-cli/SKILL.md:67`, with no further teaching). **Gap, not a match**: this pack has no dedicated `InferRules` guidance; the target's planned ladder step 3 (InferRules) isn't covered anywhere here beyond the name.
17. **Verified constructor/`compile()` signature tables, "read off the installed wheel, not copied from prose"** — `dspy-optimizer-selection/reference.md:9-63`: exact keyword-only vs positional differences for `SIMBA`, `Ensemble`, `KNNFewShot`, `BootstrapFinetune`; a table of which `compile()` call shape differs per optimizer. **[adopt-as-reference]** — saves a debugging cycle the day the target actually calls one of these; verified against dspy 3.3.1 by inspection, which is exactly the discipline `check_dspy_surface.py` re-verifies mechanically.
18. **BetterTogether's post-3.2.0 named-kwargs API, explicitly checked for staleness** — `dspy-gepa-optimizer/SKILL.md:136-157`, guarded by `test_skill_correctness.py` rule 4. **[catalogue]** — not currently relevant to the target (no multi-stage optimizer chain planned), but if a future ladder chains `BootstrapFewShot` then `GEPA`, this is the right call shape.

### RLM (job 3) patterns
19. **`dspy.RLM` is upstream-Experimental and was already renamed once mid-3.3** — `dspy-rlm-module/reference.md:5` states this plainly ("its docstring warns the class may change... already moved twice between 3.2.1 and 3.3.1") and the surface check pins both the old and new names (`max_iterations`/`max_iters`, `interpreter`/`interpreter_factory`) so a *reversion* is caught too (`check_dspy_surface.py:146-153`). **[adopt]** — directly actionable: `rlm_ingest.py` in the target uses `dspy.RLM("document: str, task: str -> candidates: str", max_iters=iters)` with the *current* correct name, but has zero protection against a future DSPy release changing it again. Adding one assertion (`"max_iterations" not in inspect.signature(dspy.RLM.__init__).parameters`) to the target's own venv-setup or a smoke test would close this.
20. **`sub_lm` for cheap inner calls; outer LM only orchestrates** — `dspy-rlm-module/SKILL.md:14,21-32,103`. **[adopt]** — `rlm_ingest.py:158-160` configures a *single* free-tier LM for both outer and inner calls (no `sub_lm=` passed at all). Given the target's own comment that free OpenRouter models are already a scarce/flaky resource (`"free, and it answers a structured-output request — 18 of the 24 free models... do not"`), passing a distinct, even-cheaper `sub_lm` (or simply the same free model explicitly, to make the choice visible) is a one-line, well-evidenced improvement.
21. **`max_llm_calls` (default 50) budgets the whole RLM invocation, separate from `max_iters`** — `dspy-rlm-module/reference.md:43`. **[adopt]** — `rlm_ingest.py` sets `--iters` (default 12) but never sets `max_llm_calls`; a single call can still fan out to 50 sub-LM calls by default, silently, which matters given the target explicitly worries about rate-limited free models.
22. **The verification cascade as the metric (Tier1 syntactic / Tier2 semantic / Tier3 pragmatic, fail-fast)** — `dspy-rlm-workflow/SKILL.md:118-134`, `reference.md:92-107`. **[adapt]** — `rlm_ingest.py`'s own `verified()` function (lines 140-152) is already a hand-rolled Tier-1-only check (does the cited line actually contain the term). The pack's three-tier shape suggests an explicit Tier 2 (candidate list resembles the human gold list's *density*, e.g. is the count plausible) and Tier 3 (a second, cheap judge model scoring "does this read like a reconstruction") that the target does not yet have — directly useful since the target's own failure mode ("it was about to reconstruct the document from its own truncated scrollback") is exactly what a Tier-1-only check cannot catch if the reconstruction happens to cite real lines.
23. **`validate_dag()` — never let the LM emit execution order; check for cycles/unknown ids in plain Python** — `dspy-rlm-workflow/reference.md:44-69`. **[catalogue]** — not directly applicable (the target's census step isn't a dependency graph), but the general principle ("do not ask the LM to order the work — it will get it wrong on the day it matters") is the same reasoning behind the target's `read.py`/`quotes.py` line-verification design.
24. **`dspy-rlm-hooks`: pre/post iteration & execution hooks, `stop=True` early exit, speculative execution with a purity requirement** — `dspy-rlm-hooks/SKILL.md:1-147`. **[catalogue]** — the "**Order is load-bearing**: `enable_rlm_hooks` overwrites `_execute_code`, so calling it after `enable_rlm_speculation` silently disables speculation. No error, just no speedup" trap (line 92-94) is a good general caution about monkeypatch-based instrumentation, but this package **patches private DSPy internals** (SECURITY.md quoted at line 34), which conflicts with the target's own extreme caution about anything not "standard-library." Its offline benchmark harness (`python -m dspy_rlm_hooks.benchmark --variants default spec --repeats 5`, no LM/API key needed, line 115-129) is a genuinely good idea for measuring RLM-loop overhead, but adopting the package itself is premature until the target has an RLM step worth instrumenting (matches the plugin-plan's own verdict, §Part 2: "adopt as a dependency, later").
25. **RLM tools are kwargs-only, typed, docstring-introspected; `verbose=True` for debugging a hanging RLM** — `dspy-rlm-module/reference.md:72-87`, `SKILL.md:105`. **[adopt]** — trivially adoptable in `rlm_ingest.py`, which currently passes no `tools=` at all; giving the RLM a `count(term)` or `grep(pattern)` tool over the document (rather than relying purely on the sandboxed `document` variable) is exactly what the skill recommends for "a census is counting, and a model that can compute over the text does not have to be believed."

### Wiki-compile / knowledge-store patterns (job 4 / open problems)
26. **Two-phase compile: extract everything, then merge, so the Nth source doesn't overwrite the 1st** — `dspy-wiki-compile/SKILL.md:26,93-96,118-119` (anti-pattern #1: "Merging inside the extraction loop; the second source then overwrites the first"). **[adopt]** — the target's own `reconcile.py` already does something structurally similar (census frozen before wiki is consulted — "extraction's independence is what makes reconciliation safe"), but this pack's phrasing of the anti-pattern is a good explicit check to add to a review checklist for any future multi-document batch tool.
27. **Citation model is `{file, start, end, quote}` line-range + substring check, not a page name** — `dspy-wiki-compile/reference.md:16-17`, anti-pattern "Storing citations as page names instead of line ranges; the lint can then prove nothing." **[skip — already superior]** the target's own `^[Lnn]` + `quotes.py` normalisation-based check is stricter (checks the *exact words*, not just substring-in-range) — the target already caught a defect class (`"das Management"` vs `"dem Management"`) that this pack's simpler `quote.strip() in "\n".join(lines[...])` substring check would *not* catch, since a near-miss substring can still literally be "in" the joined lines if padding/whitespace lines up. Worth noting as a place where the target is ahead, not behind.
28. **`Diff{reinforced, challenged, new, gaps}` printed to the human before any write, `challenged ⊆ conflicts`** — `dspy-wiki-compile/SKILL.md:41,102`. **[adapt]** — the target's `reconcile.py` output (per-document, per-page decisions) doesn't currently separate "reinforced" vs "new" vs "gaps" as a named structure; this shape is a good candidate template for `reconcile.py`'s output format, especially "gaps" (what the batch leaves unanswered), which the target does not currently surface as a distinct category.
29. **Health (free, deterministic) runs before lint (LLM-based)** — `dspy-wiki-compile/SKILL.md:106`, `reference.md:78-91`: broken links, unindexed pages, stale source hashes, orphans are all free checks that should run before spending tokens on semantic checks. **[adopt]** — matches the target's `relations.py`/`wiki_index.py` design exactly (already free/deterministic); the explicit ordering principle ("Health before lint") is worth stating as a rule if the target ever adds an LLM-based semantic check on top.
30. **`dspy-clarify`'s deterministic "meaning kept" metric — no smuggled terms, no added quantifiers** — `dspy-clarify/SKILL.md:96-107`: checks that no glossary term appears in the output absent from claim+source+context, and no quantifier (*alle, immer, nie, all, never, only*) the source doesn't state. **[adopt-as-pattern]** — this is a precise, mechanical version of the target's P12/P26 ("quote, never paraphrase") and P13 ("never merge two sources' readings into one definition"); directly reusable as a check *shape* for a future model-assisted census/note step: "did the model's rewrite introduce a universal quantifier the source lacks."
31. **`clarify`'s verdict enum `clear | needs-author | not-promotable`, with "asking scores as high as resolving" built into the gold set discipline** — `dspy-clarify/SKILL.md:100,124-126`. **[adopt-as-pattern]** — matches the target's own `status: asked` construct and "conflict detection is never mechanised" principle; a future model-assisted reconciliation step could use exactly this enum shape (never resolving ambiguity itself, only naming it), while keeping conflict detection itself human/judgement (P13 is respected because `verdict` only routes to a human question, it never decides the conflict).
32. **Deep-refine's evidence labels (`HIGH/MEDIUM/LOW`) and "review is not approval" gate** — `dspy-deep-refine/SKILL.md:103-123`. **[catalogue]** — relevant if the target ever builds a model-assisted "what should the wiki fix" loop over its own `Wiki/questions/`; not currently a live job, but the HIGH/MEDIUM/LOW evidence taxonomy (exact edge exists = HIGH; both endpoints exist but relation inferred = MEDIUM; ambiguous/bare name = LOW) is a good template for scoring a model's proposed page merge.

### Production / cost / cache patterns
33. **`dspy.configure_cache(restrict_pickle=True)`** — `dspy-production/SKILL.md:46-60`: disk-cache deserialization uses pickle by default; restrict it or set a `safe_types` allowlist. **[adopt]** — the target hasn't discussed caching at all yet (P18 says "repeats, cache off" — the target already disables caching outright for reproducibility, which sidesteps this entirely, but worth flagging as the reason *why* if caching is ever turned on for cost reasons).
34. **State-only JSON save is the default; whole-program cloudpickle save executes code on load** — `dspy-production/SKILL.md:25-44`, `dspy-fundamentals/SKILL.md:70-84`. **[adopt]** — directly relevant the moment the target saves a compiled `fold()`/one-term-or-two program: use `save_program=False` always, never accept a cloudpickle artifact "from a registry you do not control" — a security-relevant default worth stating explicitly in a future `Plan/concept/model-artifacts.md`.
35. **Measure cost with the cache disabled at least once; a warm-cache benchmark "looks free and tells you nothing"** — `dspy-production/SKILL.md:73-76`. **[adopt]** — directly applicable to `rlm_ingest.py`'s free-tier-model economics discussion; the target should measure `max_llm_calls`/latency with `cache=False` explicitly stated as the honest number.
36. **`dspy.inspect_history(n=3)` as the first debugging step** — `dspy-production/SKILL.md:113-127`: "shows the rendered prompt... most 'the model ignored my instruction' bugs are visible in one line of it." **[adopt]** — cheap, universally useful the moment the target debugs any RLM/model call gone wrong (e.g. the `rlm_ingest.py` failure mode described in its own docstring).
37. **Callbacks run synchronously in the call path; never log slow things inline; sample at high volume** — `dspy-production/SKILL.md:128-156`. **[catalogue]** — not urgent (the target has no production service), but relevant if `rlm_ingest.py` grows an observability layer.

### Small, general-purpose ideas worth cataloguing
38. **`docs/CHANGELOG.md` as the single place "corrections vs. the original draft" live**, referenced from `CLAUDE.md`. **[adapt]** — analogous to the target's `Plan/learnings/`, but scoped specifically to "what did we get wrong the first time," which the target currently folds into learnings files rather than a dedicated changelog; not necessarily worth splitting out, but the convention of a single append-only "we were wrong about X" file is worth noting as a lighter-weight alternative to a full decision file for small corrections.
39. **Symlink-based local install, idempotent, with `--verify` and `--dry-run` flags** — `scripts/install.sh:1-155`. **[skip]** — not applicable; the target has no plugin-distribution concept, and its own `.claude/skills/` and `.agents/skills/` are checked into the repo directly rather than symlinked from elsewhere.
40. **`docs/kohaerenz-protokoll-plugin-plan.md` Part 5 "What not to do" list** (do not let tools write to canon without a decision; do not widen an enum unilaterally; do not adopt refrag as a package; do not copy unlicensed TARA source; do not introduce a second skill graph; do not move a DSPy pin unilaterally; do not translate canon prose; do not skip a recall measurement). **[adopt-as-pattern]** — this whole list is already close to the target's own PRINCIPLES; the specific item "do not skip the recall measurement... an unmeasured retriever that returns plausible passages will make the conflict check look like it is working" is a sharp, directly reusable warning for any future retrieval component the target builds (e.g. over `Wiki/index.json` or qmd).
41. **`docs/compounding-wiki-extension-plan.md`'s "suppression is visible, never silent" decision (D5)** — a gate that suppresses a previously-rejected finding must still report it in a "suppressed" section citing the learning's id; the exit code stays driven by unsuppressed findings only. **[adopt-as-pattern]** — this is a precise, reusable instance of P23 ("a guard reports what it could NOT check") applied to *suppression* rather than coverage; directly relevant if the target ever builds a mechanism to stop re-raising a judgement that has already been made (e.g. `judgements.py`'s replay could grow a "this was already decided, suppressed here" annotation rather than silently filtering).

## 4. Conflicts with the principles (traps worth naming)

- **`dspy-refrag`'s headline feature does nothing** (§ read from `dspy-refrag/SKILL.md:41-58`): selection is computed but never used to shrink the prompt — "the sensor changes a boolean in the prompt. It does not remove unselected text." This is a **"metric that cannot fail" analogue at the package level**: a component that *looks* like it's doing work (selecting, annotating `selected: bool`) while doing nothing measurable, exactly the shape of P24 ("done is a measurement") and the target's own retired-pipeline coverage-term war story (`coverage()` returning 1.0 when passed nothing). If the target ever imports `dspy-refrag` wholesale rather than the one vendored file (`sensor_advanced.py`), it would silently violate P24.
- **`drg-kg` silently returns an empty graph with only a log warning when no LM is configured** (`dspy-drg-kg/SKILL.md:90-96`), unless `DRG_REQUIRE_LM=1`/`DRG_PRODUCTION=1`/`DRG_STRICT=1` is set. This is the *exact* failure mode P23 exists to prevent ("a guard reports what it could NOT check" — here, a missing LM key silently produces a *complete*, confidently-empty result instead of an error). The target's `CLAUDE.md` already flags drg-kg is installed but unused; if it's ever wired into the evaluation scorer path, this env var is not optional.
- **`enable_implicit_relationships=True` is `drg-kg`'s default**, silently adding LLM-inferred edges the caller never asked for (`dspy-drg-kg/SKILL.md:86`). Directly violates the target's "conflict detection/links are never inferred, a guessed edge is indistinguishable from a stated one once it is in the graph" principle (Decision 005). The plugin plan (§0) already caught this and mandates turning it off (`docs/kohaerenz-protokoll-plugin-plan.md:170`) — good, but it means the *target's own* `_score_sets` scorer import from `drg.evaluation._runner` (used in `rlm_ingest.py score()`) must be double-checked that it never touches the extraction/graph layers with implicit relationships on. Worth a one-line assertion in the target's own code.
- **`dspy-rlm-hooks` monkeypatches private DSPy internals** (`_execute_iteration`, `_execute_code`, `generate_action`) and its own SECURITY.md says to pin a known-good DSPy version because a release is free to rename any of them (`dspy-rlm-hooks/SKILL.md:32-36`). This is the opposite of the target's "standard-library scripts... need none of these [venvs]" design philosophy; it's a fragile dependency the moment it's adopted, and the pack's own plugin-plan defers it for exactly this reason (§Part 2 of `kohaerenz-protokoll-plugin-plan.md`).
- **`dspytools`'s rule 4 ("no try/except around imports — every package is a hard dependency")** (`dspy-tools-cli/SKILL.md:97-104`) is the *opposite* of the target's own `sources.py` design ("stays standard-library and shells out... so the tool keeps running whether or not the venv exists and says exactly how to create it when it does not"). Not a bug in dspytools, but a philosophical mismatch worth flagging if anyone considers adopting the CLI directly rather than just its optimizer names.
- **TARA's progressive-leniency retry accepts a mediocre context by lowering the bar, floor at 20/100** (`dspy-tara-rag/SKILL.md:68-83`). The plugin plan itself already flags this as the one thing *not* to adopt (§Part 3.3: "For a canon gate, the correct terminal state is an OpenQuestion, not a lowered bar") — directly matches the target's P15 ("never reached ≠ answered badly") and its own gazetteer-document precedent (mechanical exclusion criteria rather than a lowering threshold). Good negative example to cite if the target ever designs a retry loop.
- **The compounding-engineering upstream's literal-backslash-n bug, hard-coded 0.9 similarity threshold (arg ignored), and field-name mismatch causing silently-empty codified rows** (`docs/compounding-wiki-extension-plan.md`, "What not to copy" section). Not a risk to the target directly (code not vendored), but a sharp cautionary instance of exactly the "coverage term that returned 1.0" failure class the target already learned from — worth keeping as a second data point in `PRINCIPLES.md`'s catalogue of "green but broken" bugs.
- **No dict-metric anywhere is *tested for*, but the risk is real and specific**: `dspy.Evaluate`'s parallel executor literally crashes (`TypeError`) on a dict metric. If the target's own future `fold_metric` or `rlm_ingest.py score()` metric is ever hand-rolled to return a dict "because it's more readable," this pack has already hit that exact `TypeError` and tests against it in three places (`test_skill_correctness.py` rules 2 and 9, `check_dspy_surface.py:183-192`). Worth a one-line note in the target's own future metric code.

## 5. Dependencies & cost

- **This pack itself**: pure Markdown + small Python examples; `requirements.txt` is `dspy>=3.3.0,<3.4` + `pytest>=8.0`. Runs entirely inside `uv run --with dspy` / `uv run --with pytest`, no persistent install needed, no API key for anything scanned here (all dry-run paths verified offline). Fits beside the target's `.venv-dspy` (DSPy 3.3.1) without moving the pin — `requirements.txt`'s floor (`>=3.3.0`) was specifically raised because `dspy.RLM`'s 3.3.0 rename (`max_iterations`→`max_iters`, `interpreter`→`interpreter_factory`) breaks on 3.2.x; the target is already on 3.3.1 so no conflict.
- **`drg-kg[extract]`** (already installed in target per its CLAUDE.md): needs `pip install "drg-kg[dspy]"` for extraction (base install has no DSPy); requires `DRG_REQUIRE_LM=1` in any pipeline use; API keys needed only when actually extracting (the target currently uses it only for its evaluation scorer, `_score_sets`, which appears to be graph-free — worth confirming `drg.evaluation._runner` doesn't itself require an LM).
- **`dspy-rlm-hooks`** (not currently installed in target): `pip install dspy-rlm-hooks`, pure Python + optional MLflow; speculative execution spawns subprocesses/threads — deferred by the pack's own plugin-plan until an RLM step exists to instrument. No API key required for its offline benchmark.
- **`dspy-refrag`**: hard-imports `psycopg2` even for non-Postgres use (`dspy-refrag/SKILL.md:80-82`) — a real, avoidable dependency cost if the whole package were installed rather than vendoring `sensor_advanced.py` (self-contained, MIT, no external deps beyond stdlib math per the scaffolding file read).
- **`dspytools`**: needs Python ≥3.12 (target already has `.venv-dspytools` at 3.12 for this exact reason), plus FalkorDB+Redis for its graph/memory subsystems (not needed for the ten registry optimizers alone). Not on PyPI; installed from git, as the target's CLAUDE.md already documents.
- **`TARA`**: license file absent despite MIT badge (`dspy-tara-rag/SKILL.md:136-140`) — do not vendor code until resolved; the idea (4D scoring, progressive leniency to avoid) is free to reimplement from the paper.
- **`dspy-local-runtime`** (Claude Code CLI bridge, no API key): relevant only if the target ever needs to run DSPy through a Claude subscription instead of OpenRouter/OpenAI keys — currently moot since the target already has `OPENROUTER_API_KEY`/`TYPESAFE_API_KEY` in the environment.

## 6. Verdict

The single most valuable thing to take is the **verification discipline itself**, not any one skill's content: `scripts/check_dspy_surface.py` plus the regression-tests-with-provenance pattern in `tests/test_skill_correctness.py` are a direct, cheap, already-proven template for the target's own biggest unaddressed risk — that `.venv-dspy` pins DSPy 3.3.1 against an experimental `dspy.RLM` API that has already moved once, and nothing in the target currently re-checks that surface mechanically. Second most valuable: the two `docs/kohaerenz-protokoll-plugin-plan.md` / `compounding-wiki-extension-plan.md` files, because they already did this exact "what should we adopt from these upstreams" analysis for a recognizably related project and landed on conclusions (vendor one file from refrag, reimplement TARA's idea not its code, defer rlm-hooks, use drg-kg proposal-only with `DRG_REQUIRE_LM=1`) that the target should treat as a second opinion rather than re-derive — while remembering their file paths are stale against the current repo layout.

Leave: the third-party CLI/graph systems (`dspytools`, `dspy-rlm-hooks`'s monkeypatching, `drg-kg`'s implicit-relationships default) as installed-but-unused, exactly as the target's CLAUDE.md already does — this scan found no new evidence that any of them earn their infrastructure cost yet, and one explicit reason each (FalkorDB/Redis duplication, private-internals fragility, silent inference into canon) to keep them parked.
