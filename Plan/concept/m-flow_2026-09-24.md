# M-flow, installed — what it would do here, and what would decide it

*2026-09-24. Written when `mflow-ai` was installed into `.venv-mflow` at the
author's request: „Install https://github.com/netzkontrast/m_flow". Everything
under **Measured** ran today. Everything under **The path that keeps the rules**
was read in the source and has not run. Nothing in this repository calls it.*

## What it is

`netzkontrast/m_flow` is a fork of `FlowElement-xinliuyuansu/m_flow` and has
no commits of its own: its head, `0d585cd` of 2026-08-03, is an upstream
commit. The package is `mflow-ai` 0.3.6, Apache-2.0, and it has a CLI, `mflow`,
with the commands `add`, `memorize`, `search`, `delete` and `config`.

It stores knowledge as a four-level graph — **Episode → Facet → FacetPoint →
Entity** — in Kuzu (graph), LanceDB (vectors) and SQLite, all file-based. By its
README, a query is embedded, vector search finds entry points at every level,
and the graph scores each Episode by the cheapest path of evidence connecting it
to those entry points — „path-cost retrieval". That is the shape of
`graphrag.py`: seeds, then spreading over typed edges. M-flow uses embeddings
where `graphrag.py` folds surfaces, and path cost where it runs PageRank.

## Where its default path collides with this project

`graphrag_2026-09-23.md` names two rules that most GraphRAG systems break on
purpose. M-flow's default path breaks both:

- **`memorize` has a model write the graph.** An LLM extracts the Facets and the
  FacetPoints — „atomic assertions" — from the text. That is paraphrase where
  P12 wants quotation, and structure inferred where decision 005 wants every edge
  stated by the prose.
- **`search` has a model write the answer.** Unless `only_context=True`, the
  retrieved context goes to a completion step. Prose over several sources is a
  merge (P13), and whether `ask` may ever produce one is open in `NOW.md`.

The third collision is about permission rather than design. **Both steps call
OpenAI by default** — `gpt-5-nano` and `text-embedding-3-large` in the code's
defaults — so `memorize` on a landed document sends that document to a third
party. Its docs list OpenRouter as a preset for the `custom` provider. That would
change who receives the text, not whether it leaves.

## The path that keeps the rules — read in the source, not run

Two entry points:

- **`m_flow.manual_ingest(ManualIngestRequest(...))`** — „Bypasses the LLM
  extraction pipeline" (`m_flow/api/v1/manual/manual.py`). The caller supplies
  the Episodes, Facets, FacetPoints and Entities, and they are only embedded and
  stored. A FacetPoint's `search_text` is indexed; its `display_only` is shown
  when retrieved and never indexed. It calls `persist_memory_nodes` directly
  rather than the pipeline, so the model probe that stops `add` should not run.
  It still embeds.
- **`m_flow.search(..., only_context=True)`** — returns the context and skips
  the completion step (`m_flow/search/methods/no_access_control_search.py`).
  With `query_type=RecallMode.EPISODIC` the context comes from
  `episodic_bundle_search`, the Episode bundles the README describes. The
  default mode is `TRIPLET_COMPLETION`.

The wiki already holds that structure, written by a person: a page, one reading
per source, the quotations with `doc:line`, and the terms the page links. So the
experiment that would decide whether M-flow earns a place is small:

1. Map each page onto the four levels. The mapping is the author's decision
   (below).
2. Load the pages through `manual_ingest`. No model writes anything.
3. Score `search(..., query_type=RecallMode.EPISODIC, only_context=True)` on
   `graphrag.py bench`'s 17 <!--state:graphrag.cases--> cases, against the
   63 <!--state:graphrag.recall_ppr-->% that PageRank reaches.

It still needs embeddings. Through a provider, OpenAI by default, they would
send the wiki's quotations, which are corpus words, so they wait on the same
yes. The alternative is local: M-flow supports `EMBEDDING_PROVIDER=fastembed`,
which its engine describes as needing „no external API calls". That is the
`embeddings` extra, and it is not installed. Whether a local model embeds German
well enough is part of what the bench would measure.

## Not installed, on purpose

- **The MCP server** (`m_flow-mcp/`). It exposes `memorize`, `search` and the
  rest as tool calls, so it carries both collisions above, and it adds a server.
- **The OpenClaw skill** (`openclaw-skill/mflow-memory`). It tells an agent to
  search memory before every answer and to store every meaningful conversation
  with `save_interaction`. That sends conversation content to a model and turns
  a memory nobody reviews into a source. It also needs Docker.
- **The suite in `selftests.py`.** It proves the package works, not this
  repository, and it takes three minutes.

## For the author

1. **May corpus text go through M-flow at all, and to whom?** The choices are
   its default (OpenAI), OpenRouter for the model, or local embeddings with
   `fastembed` and no `memorize`.
2. **If the experiment is wanted: how does a page map onto Episode, Facet,
   FacetPoint and Entity?** One obvious shape is page as Episode, one Facet per
   source's reading, each quotation a FacetPoint with its citation in
   `display_only`, and each `[[link]]` an Entity. It is a guess until you
   choose it.
