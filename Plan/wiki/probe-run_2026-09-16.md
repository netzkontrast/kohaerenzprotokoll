# Probe run — four audit documents, cheap merge model, 2026-09-16

The second live `/research-ingest`, run to answer one question: what needs
improving before the remaining documents are ingested. Four documents chosen as
the smallest audit slice, with `konsolidierung-des-hard-canon-protokolls` kept
in deliberately — it is the document that claims authority over other sources,
and audit finding #1 was about the ingest honouring that claim.

Run artifact: `tools/kpwiki/eval_runs/probe-2026-09-16.json` (git-ignored).

The Hard-Canon document asserts supersession over other sources and the ingest
did not grant it: nothing came back `supersedes`. That is the audit fix

`die-13-alter`/`tsdp` on the alter count, `juna`/`moonshine-link` on the bond's
origin. That duplication is why the ledger is keyed by entity as well as by
concept.

## What needs improving, in order

**1. Citations do not resolve — 46 of 55 lint errors.** The dominant defect by
a wide margin. A quoted fragment is not inside the lines its citation names:

    error citation-resolves …/juna.md:34 — „Moonshine-Link,“ is not inside the cited lines

It hits both source pages (written from extraction, on sonnet) and concept
pages (written from merge, on haiku), so it is not only the cheap merge model.
The failing quotes are mostly short fragments carrying trailing punctuation
(`„Ursprungs-Ich.“`, `„positive intent,“`), which suggests the quote is being
taken with punctuation the cited line does not have, or the line range is off
by the offset that markdown tables and bold markers introduce. This is the one
to fix before spending on a wider slice.

**2. Every source page busts its budget — 4 of 4.** 1,530 · 1,504 · 2,918 ·
2,695 words against a 1,000-word maximum. The ingest writes one source page per
document with every key claim on it, and an audit document yields more claims
than the budget allows. Either the budget is wrong for source pages or the page
must split; both are contract decisions.

**3. `codex_ref` is set on 19 of 22 pages that need it.** `kiko`, `lex` and
`nyx` share a slug with a codex entry and do not link to it. A small,
mechanical gap.

**4. Language discipline slips.** `report-reorienting…: claims left the source
language (en)`, and two definition sentences are not English. Canon prose is
German and engineering English; a claim must stay in its source's language.

## What the probe changed about the repo

The ingest's own lint reported 48 findings; the full `scripts/wiki_lint.py`
finds more, because the runner lints only the pages it just wrote and with a
narrower rule set. The runner's report is a first pass, not the gate.

It also exposed a regression from the Codex restructure. Rule
`no-auto-canon-page` forbids a wiki page that mirrors a file in a terminal
directory, and `Codex/` is terminal. While the codex rendered as three files
named `GLOSSARY`, `MASTER-TIMELINE` and `WORLD-AXIOMS`, the rule could never
fire. Split into one file per entry, every entry slug became a name a concept
page legitimately takes, and the rule raised 26 errors against pages that were
correct. The wiki's research understanding of AEGIS and the codex entry for
AEGIS are different layers meant to coexist, joined by `codex_ref`. The rule
now errors only on `Canon/` and, for a codex slug, warns when `codex_ref` is
missing — which is how the three real gaps above were found.

## Open: candidate findings fail the repository gate

`scripts/kp_check.py` reports `wiki health` red. Every error is on one of the
45 unreviewed candidates this run wrote; no promoted page has a finding,
because none has been promoted. That leaves a tension worth settling: the
ingest's contract says a candidate with findings is never promoted, which
treats findings on drafts as normal, while `kp_check` treats any wiki lint
error as a repository-level failure. As it stands, no draft can be in flight
without the gate being red. Whether candidate findings should gate promotion
only, or the repository too, is the author's call.
